# Commit Form Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 53 of [the step 3 index](2026-11-02-00-roadmap-step-3.md): each
entry in **Changes** has a checkbox, and below the list the user writes a
message and commits the ticked files, with their last edit included.

**Architecture:** `CommitTicksService` remembers the **unticked** paths per
device and repository, so that any new change starts ticked without being
recorded. `CommitService` is one method: flush saves, send the commit, clear the
form, refresh the status. Until plan 54, a user who has not confirmed sees the
error's text and can confirm on the Preferences page by saving.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/git-advanced.md` (GA-17 to GA-21, criteria 4, 5, 6,
23, the UI half of 19); `docs/architecture/data.md` A-4.5c.

## Global Constraints

- The shared constraints of [the step 3 index](2026-11-02-00-roadmap-step-3.md)
  apply.
- Unticked paths are in `localStorage` under
  `fb.<userId>.unticked.<repositoryId>`, as a JSON array, in `try`/`catch`.
  Paths that are no longer changes are dropped from it whenever the status
  changes (GA-17).
- The button says "Commit 2 files" and "Commit 1 file" (GA-18). It is disabled,
  with the reason available on hover, focus or tap, when the message is empty
  after trimming or no file is ticked (GA-19).
- A hint appears when the first line is longer than 72 characters; nothing is
  refused (GA-18).
- Only the paths that are both ticked and listed are sent (GA-19).
- A save that fails stops the commit, with the save's error shown _(plan's call:
  a commit must contain what the user sees, GA-20)_.

## Review Focus

- **A save failing just before the commit** must not commit an older version →
  Task 2 test `does not commit when a waiting save fails`.
- **Two quick clicks on Commit** must make one commit → Task 2 test `two quick
  clicks make one commit`.
- **A commit failing** must keep the message the user wrote → Task 2 test `keeps
  the message and the ticks when the commit fails`.
- **A full or throwing `localStorage`** only loses the memory → Task 1 test
  `keeps working when storage throws`.
- **A file changed in another tab after it was unticked and committed there**
  comes back ticked, since it left the list in between → Task 1 test `a file
  that left the list comes back ticked`.
