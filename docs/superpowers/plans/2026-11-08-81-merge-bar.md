# Merge Bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 81 of [the step 4 index](2026-11-08-00-roadmap-step-4.md): while
a merge is in progress, the bar says "Merging _origin/main_ into _main_" and how
many files are resolved, with **Abort merge**, on every tab and device.

**Architecture:** The first part of the resolution screen, and it comes before
**Pull** (plan 82), so that no conflict ever leaves the user with no way out.
`MergeStore` reads `GET …/git/merge` while `GitStatus.mergeInProgress` is true,
and on every `git.changed`, which a resolve also publishes, but not on
`files.changed`, as that would read the whole merge after every save; the status
tells it when a merge starts or ends, without a `merge.state` event _(plan's
call; it updates A-3.11)_. The bar shows `rs-merge-summary` in place of the git
status and actions.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/git-conflicts.md` (GC-2, GC-6 without **Commit
merge**, GC-23, GC-24, GC-27); `docs/requirements/git-advanced.md` (GA-4's bar);
`docs/requirements/navigation.md` (NV-9, NV-11).

## Global Constraints

- The shared constraints of [the step 4 index](2026-11-08-00-roadmap-step-4.md)
  apply.
- Exact text: "Merging _origin/main_ into _main_", "2 of 3 files resolved".
  **Abort merge** asks: "Abort the merge? Your branch and files go back to how
  they were before the pull, and the resolutions you made are lost." (GC-23).
- On narrow screens the count stays in the bar, and **Abort merge** is in the
  git actions menu (GA-7, NV-11).
- A failed abort shows a toast with its reason and leaves the merge as it was
  (GC-27), through `ApiErrorTextService`, as `CredentialFixesService` does.

## Review Focus

- **Another tab's merge starting or ending** changes this tab without a reload
  (GC-2), and a missed event is made good on reconnect → Task 1 test `follows a
  merge started elsewhere`, `reads again after a reconnect`.
- **A read answered `409 no-merge-in-progress`** means it just ended, elsewhere:
  the store ends it instead of showing an error → Task 1 test `treats no merge
  as its end`.
- **An abort with a waiting save, or one in flight:** it must be dropped or
  answered first, or it writes the merge's content over the restored file; and a
  browser draft of a conflicting file must not offer markers later → Task 2
  tests `waits for a save in flight before aborting` and `deletes the drafts of
  conflicting files, and keeps others` (ED-25).
- **A failed read** keeps the bar showing the merge, not a normal branch that
  would offer **Push** → Task 1 test `keeps the merge when a read fails`.
- **Long branch names on a phone** are shortened, with the full name on long
  press (NV-11) → Task 2 test `shortens long names on a phone`.

### Task 2: The bar and aborting

**Files:**

- Create (with `toolkit-nx`): `components/merge-summary/`,
  `dialogs/abort-merge/`, `services/merge-actions/merge-actions.service.ts`
  under `repository-screen/` (+ specs)
- Modify: `components/repository-bar/*`,
  `pages/repository-screen/repository-screen.page.*`,
  `apps/web/public/i18n/en.json`, `docs/product/mvp.md`

**Interfaces:**

- Consumes: `GitApi.abortMerge`, `MergeStore`,
  `OpenFilesService.dropForDiscard`, `OpenFilesService.deleteDrafts`,
  `DialogService`.
- Produces:
  - `MergeSummaryComponent` (`rs-merge-summary`): inputs `state: GitMergeState |
    null`, `narrow: boolean`; output `abort`.
  - `MergeActionsService.abort(): Promise<void>`, which asks, then calls
    `dropForDiscard` for each conflicting file, which waits for a save in flight
    and holds the saver, then calls the API. When that succeeds it calls
    `release` and `deleteDrafts` for the conflicting files; when it fails,
    `restore`. Plans 96, 100 and 101 add to it. Provided by the page.

- [ ] **Step 1: Write the failing tests**: `shows what merges into what, and the

      cancelling changes nothing`; `waits for a save in flight before aborting`;
      `deletes the drafts of conflicting files, and keeps others`; `gives the
      waiting save back when the abort fails`; `says why an abort failed, and
      the merge stays`; `shortens long names on a phone`; `moves Abort merge
      into the menu on a phone`.
- [ ] **Step 2: Run them and see them fail** — `npx nx test
