# Undo Merge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or

**Goal:** Plan 102 of [the step 4 index](2026-11-08-00-roadmap-step-4.md):
**Undo merge** is in the "Merge committed" notice and in the branch list, while
the backend says the merge can still be undone.

**Architecture:** One action in two places, both following
`GitStatus.undoableMerge`. Nothing is decided in the client: a stale button gets
`undo-not-allowed`, which says why.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/git-conflicts.md` (GC-22, GC-25, GC-26, GC-27,
AC-GIT-003.11, AC-GIT-003.13).

## Global Constraints

- The shared constraints of [the step 4 index](2026-11-08-00-roadmap-step-4.md)
  apply.
- The question: "Undo the merge? Your branch goes back to how it was before the
  pull. The merge commit is no longer on the branch." with **Undo merge** and
  **Cancel**.
- After an undo, a toast says "Merge undone."; the **to pull** count is back
  (GC-26).

## Review Focus

- **A waiting save at Undo:** it would make the working copy dirty and refuse,
  or land after the reset; it goes first, and then the backend decides → Task 1
  test `sends a waiting save first`.
- **The open file changed by the undo** reloads as in ED-24 → Task 1 test (end
  to end) `reloads the open file after an undo`.
- **Pushed in another tab while the question is open:** the refusal says so, and
  nothing changes → Task 1 test `says when the merge can no longer be undone`.
- **The notice dismissed:** **Undo merge** must still be reachable from the
  branch list → Task 1 test `offers Undo merge in the branch list after the
  notice is dismissed`.
