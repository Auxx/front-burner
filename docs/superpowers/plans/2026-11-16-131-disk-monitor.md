# Disk Monitor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 131 of [the step 6 index](2026-11-16-00-roadmap-step-6.md): Front
Burner watches free space on `/data` and on the repositories directory. Below
`FRONT_BURNER_LOW_DISK_THRESHOLD` (default 2 GB) new clones are refused with
"The server is running low on storage. Contact your administrator.", the log
gets a warning, and the readiness check reports `degraded`; saves, commits and
synchronisation keep working (NF-9.7, as limited in the MVP: no uploads).

**Architecture:** `DiskMonitor` in `server/core/storage` (modules.md: "disk
monitor") reads `statfs` of the data directory and of the repositories root
(plan 127), once on start and then from a housekeeping job,
`storage.disk-check`, every minute _(plan's call)_. It keeps the last free bytes
per volume and `low`. When `low` changes it logs (warn on entering, info on
leaving). It publishes no event _(plan's call: the push channel addresses users
and sessions, and the storage library knows neither; plan 132's banner reads an
endpoint instead)_. Two checks read it: `ReadinessService` (`degraded`) and the
clone job's request (add repository, **Retry clone**, **Clone again**), which
answers `507 low-storage` _(plan's call: 507 Insufficient Storage)_. A clone
already running goes on.

**Tech Stack:** `node:fs` `statfs`. No new packages.

**Spec:** `docs/architecture/non-functional.md` NF-9.7, NF-10.8;
`docs/architecture/overview.md` A-1.15 (`FRONT_BURNER_LOW_DISK_THRESHOLD`);
`docs/requirements/repo-add.md`, `docs/requirements/repo-manage.md` (the clone
requests).

## Global Constraints

- The shared constraints of [the step 6 index](2026-11-16-00-roadmap-step-6.md)
  apply.
- The message is NF-9.7's, exactly: "The server is running low on storage.
  Contact your administrator."
- When both roots are one file system, it is checked once and reported as
  `data`.
- A `statfs` that fails is logged and counts as not low: a broken check must not
  block clones.
- A size parser for `KB`, `MB`, `GB` (1024-based) is added to the config if none
  exists yet; `0` turns the check off _(plan's call)_.

## Review Focus

- **Space that comes back** clears `degraded` and lets clones start again
  without a restart → test `leaving low space allows clones again`.
- **Only the repositories volume is low**: still low → test `either volume below
  the threshold is low`.
- **Saves and commits during low space** still work → test `low space refuses
  only clones`.
