# Full Disk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or

**Goal:** Plan 133 of [the step 6 index](2026-11-16-00-roadmap-step-6.md): when
the disk is full, a save answers "Server storage is full — not saved" and the
web client keeps the draft and retries; a git job that hits `ENOSPC` is handled
like an interrupted one and its temporary files are removed (NF-9.8).

**Architecture:** One helper, `isStorageFull(error): boolean` (`ENOSPC`, and
`EDQUOT` _(plan's call)_), in `server/core/storage`. The save path in
`server/feature/files` maps it to `507 storage-full`; the other file actions
(create, rename, delete) do the same. In the git engine, a command whose stderr
says "No space left on device" is the same condition. The job runner already
ends interrupted jobs by type (NF-9.5, A-6.8); a git job that fails with
`storage-full` takes the same path: a pull resets a half-applied merge to its
recorded commit (D-4.6), a clone removes its partial copy (AR-54). In the web
client, the save queue treats `storage-full` like a lost connection: the draft
stays in IndexedDB and the save is retried with backoff (NF-3.2), and the save
status shows NF-9.8's text in place of "Not saved — offline, retrying".

**Tech Stack:** as before. No new packages.

**Spec:** `docs/architecture/non-functional.md` NF-9.8, NF-9.5, NF-3.1 to
NF-3.3; `docs/requirements/editor.md` (the save status).

## Global Constraints

- The shared constraints of [the step 6 index](2026-11-16-00-roadmap-step-6.md)
  apply.
- The text is NF-9.8's, exactly: "Server storage is full — not saved".
- A full disk never leaves a half-written file in the working copy: the save
  writes to a temporary file and renames it, or truncates nothing, whichever the
  save path does now; a test pins the file's old content.
- SQLite's own rollback (NF-9.8's third bullet) needs no code; a test pins it.

## Review Focus

- **A save that fails for a full disk** keeps the file's old content on disk →
  test `a save on a full disk leaves the file as it was`.
- **Typing goes on** while saves fail, and the save goes through once space is
  back → test `retries a storage-full save and clears the draft when it goes
  through`.
- **A pull that hits a full disk** mid-merge leaves the branch as it was → test
  `a pull that runs out of space is reset to its recorded commit`.
- **A database write on a full disk** leaves the database consistent → test `a
  failed transaction for ENOSPC changes nothing`.
