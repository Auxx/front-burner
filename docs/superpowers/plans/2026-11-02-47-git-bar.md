# Git Status in the Bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 47 of [the step 3 index](2026-11-02-00-roadmap-step-3.md): the
repository screen's bar shows the current branch and "2 to push, 3 to pull", or
"Not published", or "main · no commits yet".

**Architecture:** One presentational component in `rs-repository-bar`, fed by
`GitStatusStore`. It is plain text for now: step 4 turns the branch into the
button that opens the branch list (GA-36), and plan 58 adds **Push** next to it.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/git-advanced.md` (GA-7's branch and counts, GA-42's
header); `docs/requirements/navigation.md` (NV-9, NV-11).

## Global Constraints

- The shared constraints of [the step 3 index](2026-11-02-00-roadmap-step-3.md)
  apply.
- Counts are in words: "2 to push", "3 to pull", "2 to push, 3 to pull", nothing
  when both are zero, "Not published" for a branch without an upstream (GA-7).
  Singular and plural come from Transloco's `messageformat`, as the other counts
  do.
- A repository without commits shows exactly "main · no commits yet" (GA-42),
  and not "Not published".
- A long branch name is shortened with an ellipsis, and its full name is
  available on hover, focus or long press (NV-11).
- The counts stay visible on narrow screens (GA-7, NV-11).

## Review Focus

- **Before the first status arrives,** the bar shows nothing rather than a flash
  of "Not published" → test `shows nothing until the status has loaded`.
- **A detached `HEAD`** shows "No branch" _(plan's call)_ rather than an empty
  space → test `shows No branch for a detached HEAD`.
- **A status read failing after one succeeded** keeps the last branch and counts
  → covered by plan 46's store; test `keeps showing the last status`.
- **A 200-character branch name at 320 px** must not push the user menu out of
  the bar → end-to-end test `the branch and counts stay in the one bar`.
