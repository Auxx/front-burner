# Delete API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 18 of [the step 2 index](2026-10-28-00-roadmap-step-2.md): the
API deletes files, symbolic links (never their targets) and folders of any size,
and the folder is gone from the working copy at once.

**Architecture:** In `server/feature/files`, inside plan 17's
`WorkingTreeGuard.change`. A file or a link is unlinked. A folder is moved into
`tmp/` with one rename and a **Delete folder** job removes it there, as
`docs/architecture/jobs.md` already decides (FB-40, NF-5.3); since the rename is
instant, the request never needs to return `202`. `tmp/` is emptied on every
start, so an interrupted job loses nothing.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/file-browser.md` (REQ-FILE-001: FB-23, FB-26,
FB-37, FB-40; criteria 26 and the API halves of 11, 18 and 20);
`docs/architecture/jobs.md` (the Delete folder row), A-6.5; `non-functional.md`
NF-5.1, NF-5.3, NF-2.8.

## Global Constraints

- The shared constraints of [the step 2 index](2026-10-28-00-roadmap-step-2.md)
  apply.
- Delete is allowed for files of every kind, symbolic links and folders; it is
  refused for submodules and for the root folder with `400 entry-not-deletable`
  ("This can't be deleted.") (FB-23, FB-37).
- A symbolic link is resolved with `symlinkLeaf: true` and removed with
  `unlink`; nothing ever follows it (A-7.6, AC-FILE-001.11).
- The folder's name in `tmp/` is `delete-<random UUID>`, never derived from the
  user's path. The job's payload is that name and nothing else (A-6.3).
- The job type is `files.delete-folder`, pool `housekeeping`, `onInterrupted:
  'fail'`, with the repository ID set (A-4.5b).
- After a delete, `files.changed` names the parent folder.

## Review Focus

- **A symbolic link to a folder outside the working copy** must disappear, and
  the folder it points to must keep every file → Task 1 test `AC-FILE-001.11:
  deleting a symbolic link removes only the link`.
- **A folder whose path goes through a symbolic link** (`link/sub`) must be
  refused, so that nothing outside the working copy is moved into `tmp/` → Task
  1 test `refuses a folder through a symbolic link`.
- **`path=''`** (the whole working copy) must be refused → Task 1 test `refuses
  the root folder`.
- **The job failing to remove the trash** (a file made unwritable) must not turn
  into an error for the user, whose folder is already gone → Task 2 test `logs a
  failed removal without failing the delete`.
- **A delete during a merge** must leave the folder where it was → Task 1 test
  `refuses a delete during a merge`.

### Task 2: The Delete folder job

**Files:**

- Create: `libs/server/feature/files/src/actions/delete-folder.job.ts` (+
  `.spec.ts`)
- Modify: `src/files.module.ts`

**Interfaces:**

- Consumes: the job runner's `JobTypeDefinition` registration, as `CloneJob`
  registers itself.
- Produces: `DeleteFolderJob` — type `files.delete-folder`, handler `rm(join(
  tmpDir, payload.name), { recursive: true, force: true })`; a payload name that
  is not `delete-<uuid>` fails the job without touching the disk. A failure is
  logged at `warn` with the job ID only and is not published to the user.
