# File Browser, Editor and Live Preview — Plan Index

> Status: **Draft, for review**

Plans 1 to 12 ([the step 1 index](2026-10-26-00-roadmap.md)) finished MVP step
1, except the leftovers listed at the end. This index splits MVP step 2
(`docs/product/mvp.md`, "Order of work") into small plans, numbered on from 13.
Each plan is one branch and one pull request, leaves CI green, and can be shown
to someone when it is merged. At the end of step 2 the operator can browse a
repository, create, rename and delete files and folders, and edit Markdown files
with a live preview, but not commit them.

There is no separate design spec: the requirements and the architecture
documents are the spec. Each plan names the requirement IDs it implements and
records its own decisions as _(plan's call)_; a decision that changes or adds to
an architecture document updates that document in the same pull request.

## Two parts

**Part A, the file browser (plans 13 to 22), is written now.** Its plans are
linked below.

**Part B, the editor and the preview (plans 23 to 33), is outlined only.**
`mvp.md` (Risks, "Typing speed on phones") requires the typing check on a real
mid-range phone (A-8.11, NF-2.4) to happen _before the editor is built_, so that
a slow result can still change its design. Part B's plans are written once that
check has been made and its result recorded in `docs/architecture/spikes.md`
(spike 3). The outline below fixes their order and scope, not their design.

## Shared constraints

The shared constraints of [the step 1 index](2026-10-26-00-roadmap.md) apply to
every task of every plan here, with these additions:

- **Opening a repository's files is always scoped to its owner.** Every files
  endpoint finds the repository with `RepositoryQueries.find(userId, id)` (plan
  14) and answers `404 not-found` for another user's repository, exactly as for
  one that does not exist (FB-2, AC-FILE-001.2).
- **Every client path goes through `resolveInWorkingCopy`** (plan 13). No files
  endpoint builds a file system path any other way (FB-5, A-7.6).
- **Every change to the working tree runs inside `WorkingTreeLock.run`** and is
  refused with `409 merge-in-progress` while a merge or rebase is in progress
  (FB-26, A-5.3). Listing and reading never take the lock (A-5.3).
- **Paths on the wire** are POSIX, relative to the working copy root, without a
  leading or trailing `/`; the root folder is `''`. A path names an entry as it
  is on disk; new names are stored in NFC (FB-28).
- **Per-device memory** (pane sizes, the collapsed tree, expanded folders, the
  last open file) is in `localStorage` under `fb.<userId>.<key>`, read and
  written in `try`/`catch`; a throwing or empty storage only loses the memory
  (FB-8, FB-12, FB-14).
- Tests that cover an MVP criterion start their title with its ID, and every
  plan updates the "Implementation status" table of `docs/product/mvp.md` as its
  "Keeping it up to date" note says.

## Left out of these plans

Each is deferred to the plan or step that builds it, not dropped:

- **Part B** (plans 23 to 33), as said above. Until it is merged, selecting a
  Markdown file shows its name and "The editor comes in a later version." in the
  editor area (plan 16), and FB-36's and FB-39's waiting saves have nothing to
  flush or drop.
- **The branch, git status and actions in the combined bar** (NV-9, GA-7) and
  the conflict list in place of the tree (FB-26, GC-7): step 3 and 4. The
  backend's refusal during a merge (FB-26) is built now.
- **Step 1 leftovers**: the Preferences page and its user-menu item, the version
  line and the new-version banner (NV-7, NV-15, NF-7.6), the offline banner
  (NV-15), NV-16, and **Repository settings** in the switcher (REQ-REPO-003,
  step 5). Until then, the switcher's **Repository settings** and the
  non-openable screen's management link lead to "Page not found".
