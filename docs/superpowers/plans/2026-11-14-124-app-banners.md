# App Banners Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 124 of [the step 5 index](2026-11-14-00-roadmap-step-5.md): every
page with the app header shows, directly below it, "A new version of Front
Burner is available." with **Reload** once the backend's version differs from
the web client's, and "You're offline. Changes are kept and saved when you're
back online." while the browser is offline (NV-15).

**Architecture:** An HTTP interceptor in `web/core` compares each API response's
`X-Front-Burner-Version` (plan 123) with `APP_VERSION` and sets a `newVersion`
signal; `OnlineStatus` follows the browser's `online` and `offline` events. A
`shell-app-banners` component under the app header shows both, one above the
other. On the repository screen, whose bar replaces the app header (NV-9), the
banners are below its bar _(plan's call: NV-15 says every page that has the app
header, and the bar is that page's app header)_.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/navigation.md` (NV-15, NV-16, AC-APP-001.11);
`docs/architecture/web-client.md` (A-8.7); NF-3.2, NF-7.6; ED-17.

## Global Constraints

- The shared constraints of [the step 5 index](2026-11-14-00-roadmap-step-5.md)
  apply.
- The new-version banner cannot be dismissed. **Reload** first sends a waiting
  save of the open file (ED-17, as NV-12 does: `OpenFilesService.flushAll`),
  then reloads; a save that fails keeps the browser draft (NF-3), and the reload
  goes ahead.
- A response without the header (a proxy's error page) changes nothing.
- The offline banner goes away on its own (NV-15). It is a `status` region, so
  that a screen reader announces it once; the new-version banner too.
- Page notices stay below these banners (NV-16).

## Review Focus

- **A new version during an edit:** **Reload** saves first → test `saves before
  reloading`.
- **A response without the header** shows no banner → test `ignores a response
  without the header`.
- **Offline and back** → end-to-end test `AC-APP-001.11`, with the context set
  offline.
