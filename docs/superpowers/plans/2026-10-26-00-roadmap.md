# Login, OIDC, Dashboard and Adding Repositories — Plan Index

> Status: **Accepted**

The walking skeleton ends with administrator onboarding by username + password.
This index splits the next part of MVP step 1 (`docs/product/mvp.md`, "Order of
work") into twelve small plans. Each plan is one branch and one pull request,
leaves CI green, and can be shown to someone when it is merged.

There is no separate design spec for this work: the requirements and the
architecture documents are the spec. Each plan names the requirement IDs it
implements and records its own decisions as _(plan's call)_; a decision that
changes or adds to an architecture document updates that document in the same
pull request.

## Shared constraints

Every task of every plan includes these, in addition to its own plan's Global
Constraints:

- Each plan works on its own branch off `master` (named in the table above).
  `gh` is not installed: push only when the user asks, then hand them the pull
  request title and body.
- Load the `development-workflow` skill before the first edit. Angular artefacts
  (pages, components, services, directives) are created with the
  `@hexmode/toolkit-nx` generators (`toolkit-nx` skill); guards, interceptors
  and models with no generator follow that skill's rules. Server libraries are
  created with `@nx/nest:library`, shared ones with `@nx/js:library`. Load the
  `ai-tools` skill before writing any one-off script.
- **Exact versions** in `package.json` (`npm install --save-exact`); every
  `@nx/*` package stays at **23.3.1**; all `@nestjs/*` stay on 11.x.
- Every new project has exactly one `scope:` and one `type:` tag (A-2.4, A-2.5);
  `npm run check:tags` passes. Import aliases are
  `@front-burner/<project-name>`. Server Vitest configs use `unplugin-swc` (copy
  `apps/server/vitest.config.mts`).
- Every request and response body is a named Zod schema in `shared/contracts`
  (`.meta({ id })`, A-3.3, A-3.4); server DTOs are built from them as in
  `libs/server/feature/auth/src/onboarding/onboarding.dto.ts`. Response schemas
  never contain a secret (A-3.5).
- After any change to a controller or a contracts schema: `npx nx run
  web-api-client:generate` and commit `apps/server/openapi.json` and
  `libs/web/api-client/src/generated` (CI's drift check, A-3.7).
- New error codes go into `ERROR_CODES` in
  `libs/shared/contracts/src/errors/error-codes.ts` when they are shared;
  feature codes are thrown with `ApiErrorException` and get an English fallback
  message. Every code the web client can meet gets a text under `errors.<code>`
  in `apps/web/public/i18n/en.json`.
- No secret in a log, a response, a URL or browser storage: passwords, tokens,
  refresh tokens, one-time codes, client secrets, private keys, passphrases
  (AO-38, LG-44, LG-66, AR-17). Email addresses, repository names and file paths
  only at `debug`; remote URLs always without credentials (NF-10.5).
- English UI text only through Transloco, keys in `apps/web/public/i18n/en.json`
  under `<project-name>.<Component>.<key>`.
- Pages are usable at 320 px wide (NF-12.4) and pass axe-core with no violation
  (NF-13.8); `web-e2e` runs every new page in the NF-12.2 browser matrix.
- Migration numbers in the plans (`0001_…` to `0007_…`) assume the order of the
  table above. `drizzle-kit` numbers migrations in the order they are generated,
  so a plan that merges after a parallel one regenerates its migration on top of
  `master` before merging.
- Format with `npx dprint fmt`; `npx dprint check` passes. After editing a
  document under `docs/`, run the doc ID check from `ai-tools`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Left out of these plans

Each is deferred to the plan that builds its page or feature, not dropped:

- The repository management and settings pages (REQ-REPO-003). Until then the
  header's **Repositories** link, the dashboard's **All repositories** link and
  the settings link of a cloning or failed repository lead to "Page not found".
- The repository screen (REQ-FILE-001). Until then an openable repository on the
  dashboard links to `/repositories/<id>`, which shows "Page not found", and
  nothing sets the last access time on opening (DS-7, DS-8).
- The Preferences page and its user-menu item (CA-9), the version line of the
  user menu and the new-version banner (NV-7, NV-15, NF-7.6), and the offline
  banner (NV-15).
- Encryption key rotation (NF-8.4, A-4.9): plan 3 reads values with the key ID
  they name, but the re-encryption job comes after the MVP's first release.
- Password reset (LG-48 to LG-60): without SMTP the **Forgot password?** link is
  hidden (MVP), so the Forgot password and Confirm password reset pages are not
  built.
- Disabled users (LG-24 to LG-26) beyond the login checks: there is no way to
  disable a user in the MVP. The `disabled` column and the checks are built, so
  that user management only adds the switch.
