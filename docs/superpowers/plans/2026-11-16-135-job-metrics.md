# Job and Git Metrics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 135 of [the step 6 index](2026-11-16-00-roadmap-step-6.md): the
rest of NF-10.11's metrics: job queue depth, job durations and failures by job
type, git operation durations, clones running and waiting, and free disk space.

**Architecture:** Each library registers its own metrics on `METRICS_REGISTRY`
(plan 134), so no library learns another's internals. The job runner observes
each job's end: `front_burner_job_duration_seconds{type, result}` (histogram,
`result` is `done`, `failed` or `cancelled`) and
`front_burner_job_failures_total{type}`; `front_burner_jobs_queued{type}` is
collected on scrape. The git engine times each command:
`front_burner_git_operation_duration_seconds{operation}`, `operation` being the
engine's method name from a fixed list (`clone`, `fetch`, `pull`, `push`,
`status`, `commit`, …). `front_burner_clones{state}` (`running`, `waiting`) is
the clone job type's share of the queue. `front_burner_disk_free_bytes{volume}`
(`data`, `repos`) reads `DiskMonitor` (plan 131).

**Tech Stack:** `prom-client`, from plan 134.

**Spec:** `docs/architecture/non-functional.md` NF-10.11;
`docs/architecture/jobs.md` (A-6: "Metrics cover queue depth, durations and
failures per type").

## Global Constraints

- The shared constraints of [the step 6 index](2026-11-16-00-roadmap-step-6.md)
  apply.
- Label values come from fixed sets only: job types, the engine's operation
  names, `data`/`repos`. A test reads every metric's label values after a full
  run and checks them against those sets.
- Without a token (plan 134) the metrics still exist in memory but are never
  served; recording costs nothing noticeable _(plan's call: no switch)_.

## Review Focus

- **A job that throws** counts as a failure and still gets a duration → test `a
  failed job is counted and timed`.
- **A git command that times out** is timed too (NF-11.8) → test `a timed-out
  command is timed`.
- **Housekeeping jobs** are in the metrics like others → test `every registered
  job type appears with zero`.
