# Amend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 55 of [the step 3 index](2026-11-02-00-roadmap-step-3.md): while
the last commit has not been pushed and is not a merge commit, the user can
amend it, changing its message, adding the ticked files, or both.

**Architecture:** The status answer gains `lastCommit`, with its message and
whether it can be amended, so that the form needs no second request. `amend` on
the commit request reuses plan 52's `commit` path with `--amend`; the backend
checks the rule again inside the lock, since a push can have happened meanwhile.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/git-advanced.md` (GA-19's exception, GA-22,
criterion 7); `docs/requirements/commit-author.md` CA-1.

## Global Constraints

- The shared constraints of [the step 3 index](2026-11-02-00-roadmap-step-3.md)
  apply.
- The last commit can be amended when `HEAD` exists, has at most one parent
  (`git rev-list --parents -1 HEAD`), and no remote branch contains it (`git
  for-each-ref --contains HEAD --count=1 refs/remotes`).
- The commit is `git commit --amend --reset-author --allow-empty
  --cleanup=whitespace --no-edit -F -`. `--reset-author`, with the commit
  author's variables, records the author that applies now (CA-1);
  `--allow-empty` lets a message change through when the commit has no files of
  its own.
- A refused amend is `409 amend-not-allowed`, checked inside the lock.
- `lastCommit.message` is `git log -1 --format=%B`, without a trailing line
  break; `lastCommit` is `null` without commits. The message is sent only when
  the commit can be amended; it can be large, and nothing else needs it.

## Review Focus

- **A commit pushed in another tab while Amend is ticked** must be refused, and
  the user told, since an amend then would need a force push → Task 2 test
  `refuses an amend of a commit that was pushed meanwhile`.
- **Unticking Amend after editing the filled-in message** must not leave the old
  commit's message to be committed by accident → Task 2 test `unticking Amend
  clears a message it filled in, and keeps one the user changed`.
- **A merge commit** must not offer it → Task 1 test `a merge commit cannot be
  amended`.
- **The first commit of a repository (no parent)** can be amended → Task 1 test
  `a root commit can be amended`.
- **A commit that only a remote branch other than the upstream has** counts as
  pushed → Task 1 test `a commit on any remote branch cannot be amended`.
