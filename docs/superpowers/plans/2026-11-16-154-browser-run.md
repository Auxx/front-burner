# Full Browser Run Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 154 of [the step 6 index](2026-11-16-00-roadmap-step-6.md): every
test of every project passes in Chromium, Firefox and WebKit on desktop, and in
Chromium and WebKit with a phone viewport (NF-12.2). The nightly workflow, whose
schedule is off, is run by hand to find out, and what fails is fixed.

**Architecture:** A run and its fixes. The operator starts `Nightly` from the
Actions tab on this branch (`workflow_dispatch`) and shares the run's link. Each
failure is sorted: a product bug (fixed here, test first), a flaky test (fixed,
never retried away), or a browser difference the product accepts (recorded in
`docs/architecture/web-client.md` with the reason, and the test adjusted for
that browser only). The run is repeated until it is green, and its link is
recorded in the checklist.

**Tech Stack:** as before.

**Spec:** `docs/architecture/non-functional.md` NF-12.1 to NF-12.3;
`.github/workflows/nightly.yml`.

## Global Constraints

- The shared constraints of [the step 6 index](2026-11-16-00-roadmap-step-6.md)
  apply.
- `nightly.yml`'s schedule stays commented out (the index's "Left out").
- `test.skip` for one browser needs a comment with the reason and a link to the
  record in `web-client.md`.
- Plan 149's new baseline tests are in this run; if plan 149 is not merged yet,
  this plan runs again after it, before plan 157.

## Review Focus

- **WebKit on a phone viewport**, the closest to Safari on iOS, is the likeliest
  to fail: its failures are read first, and anything that touches the on-screen
  keyboard or touch is checked again by hand in plan 155.
