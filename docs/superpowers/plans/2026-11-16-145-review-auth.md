# Review: Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 145 of [the step 6 index](2026-11-16-00-roadmap-step-6.md): the
first part of the MVP's security review. Everything that decides who a request
comes from and what it may touch is read against its rules, each rule gets a
test that proves it or a finding, and small findings are fixed here.

**Architecture:** A review, recorded in a new document,
`docs/wiki/security-review.md` _(plan's call: a wiki page, since it records a
check at one commit, not a rule)_, with one section per plan of Part D. Each
section has a table: the rule, where the code enforces it, the test that proves
it, and the outcome (**Holds**, **Fixed in this branch**, or **Plan
&lt;number&gt;**). The code is read, not only the tests: a rule with a test but
a second way around it is a finding.

**Tech Stack:** as before.

**Spec:** `docs/architecture/security.md` A-7.1 to A-7.5;
`docs/requirements/auth-onboarding.md` (AO-x); `docs/requirements/auth-login.md`
(LG-x); `docs/requirements/auth-password-policy.md`;
`docs/architecture/non-functional.md` NF-11.4, NF-11.5.

## Global Constraints

- The shared constraints of [the step 6 index](2026-11-16-00-roadmap-step-6.md)
  apply.
- What to read, at least:
  - the global guard and every route marked public (A-7.2); a public route that
    should not be;
  - the auth token: algorithm pinned, expiry, the session it names still
    existing, `disabled` users refused (LG-24 to LG-26);
  - the refresh token: the cookie's flags, rotation, reuse of an old one,
    revocation on logout (LG-29 to LG-38);
  - the setup token and onboarding: compared in constant time, disabled for good
    once completed, its own limit (AO-37);
  - OIDC: `state`, `nonce` and PKCE, the issuer, verified email (AO-30);
  - ownership on every route that takes an ID (A-7.3, A-7.5's test), and
    `@AdminOnly()` on every administrator route (A-7.4), including plan 132's;
  - the limits of NF-11.4 and NF-11.5, and `trust proxy` (A-1.15): can a client
    choose its own IP?
  - the login audit log: every failure recorded, nothing secret in it (LG-66).
- A finding gets a test that fails before the fix. A finding too large for this
  branch gets a plan numbered from 158 and a row in the index's Part F.

## Review Focus

- **A route added after A-7.5's test** was written and not in its list → the
  test must find routes itself, not list them; if it lists them, that is a
  finding.
- **`X-Forwarded-For` from a client** not behind the trusted proxy → test that
  it does not change the rate limit's key.
- **A refresh token used twice** (stolen and replayed) → test what LG-x says
  happens.
