# Accessibility Hand Pass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 156 of [the step 6 index](2026-11-16-00-roadmap-step-6.md): the
manual accessibility pass before the release (NF-13.8): the whole MVP with the
keyboard alone, with VoiceOver on iOS, and with NVDA on Windows, against WCAG
2.2 AA (NF-13.1, NF-13.3 to NF-13.7; NF-13.2 as limited in the MVP).

**Architecture:** A hand check, as plan 155. **The operator runs the screen
readers**; the agent writes the script and turns the results into records and
fixes. The script, in `docs/wiki/release-checks.md`'s "Accessibility" section,
walks exit criteria 1 to 11 three times (keyboard, VoiceOver, NVDA) and asks at
each step what WCAG checks: is the focus visible and in order, is there a trap,
what does the screen reader announce for each control, status change and error,
is a live change (a clone's progress, a save's status, a toast, a banner)
announced once and not too often. The editor follows NF-13.3's own rules (`Tab`
inserts a tab; `Esc` then `Tab` leaves). The conflict screens are checked with
**Edit conflict markers** and keeping a whole version, the MVP's methods.

**Tech Stack:** none new.

**Spec:** `docs/architecture/non-functional.md` NF-13; `docs/architecture/
design-system.md` and `docs/architecture/web-client.md` (the a11y decisions, for
example A-10.30).

## Global Constraints

- The shared constraints of [the step 6 index](2026-11-16-00-roadmap-step-6.md)
  apply.
- Each result records the OS, browser and screen reader versions.
- A finding names the WCAG success criterion it breaks; a failure is a plan
  (index, Part F) unless it is a small fix, which gets a test (a Storybook
  interaction test or an end-to-end test with `axe` or ARIA assertions) before
  it is fixed.

## Review Focus

- **Live regions that speak too much** (a clone's progress every second) → a
  script line for each live change.
- **The conflict bar** as the keyboard and screen reader route to the editor's
  **Accept** buttons, which are hidden from assistive technology (web-client.md)
  → a script line that resolves a conflict with NVDA alone.
