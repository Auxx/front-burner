# Warnings API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 108 of [the step 5 index](2026-11-14-00-roadmap-step-5.md): every
`RepositorySummary` carries the repository's warnings (RM-8), computed for the
session that asks, and clients learn when they change.

**Architecture:** `toSummary` now hard-codes `warnings: []`. A
`RepositoryWarnings` service computes them from `SyncStateStore` (plan 107) and,
for "Key locked", from `KeyUnlockStore.isUnlocked(sessionId, credentialId)` for
a passphrase-protected SSH key. Every endpoint that answers a summary passes the
session: `recent`, `list`, `get`, `open`, `add` and `details`. A change of a
stored problem publishes `repository.warning`; a key's lock already publishes
`key.locked` and `key.unlocked`, and a restart drops every stream, so clients
reread then anyway (A-3.11) _(plan's call)_.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/repo-manage.md` (RM-8, AC-REPO-003.6,
AC-REPO-003.7); `docs/requirements/repo-credentials.md` (RC-4, RC-6, RC-15);
`docs/architecture/api.md` A-3.11.

## Global Constraints

- The shared constraints of [the step 5 index](2026-11-14-00-roadmap-step-5.md)
  apply.
- Mapping, in the order of RM-8's table, without duplicates:
  `credentials-refused` from either stored problem → "Credentials refused";
  `push-not-allowed` → `cannot-push`; `host-key-changed` from either → "Server
  identity changed"; a locked protected key → `key-locked`.
- Only `ready` repositories have warnings: a failed clone shows its error, not a
  warning (RM-6, RM-8).
- `server/feature/repositories` must not import `server/feature/sync`: the
  problems are read through a small reader interface that the sync feature
  provides, or the store moves to a core library, whichever the workspace's
  boundaries allow _(implementation's call; it updates
  `docs/architecture/modules.md` if a library moves)_.
- Computing warnings for 50 repositories reads `sync_state` once, not once per
  row (NF-2).

## Review Focus

- **A key unlocked in one session** is still "Key locked" in another → test
  `key-locked depends on the session`.
- **After a restart**, every protected key is locked → test `a protected key is
  locked after a restart` (AC-REPO-003.7 itself is named by plan 120, with its
  **Unlock**).
- **Both problems refused** gives one "Credentials refused" → test `does not
  repeat a warning`.
- **A failed clone** has no warning → test `a repository in error has no
  warnings`.
- **One query** for the list → test `reads the problems of all repositories at
  once`.
