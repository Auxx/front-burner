# Safe HTML Whitelist Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 28 of [the step 2 index](2026-10-28-00-roadmap-step-2.md): a new
`web/markdown` library turns Markdown into HTML that holds only what the safe
HTML whitelist allows, and reports what it removed. The whitelist is written
once; both sanitising steps, `rehype-sanitize` on the syntax tree and DOMPurify
before the page, are built from it, and a corpus of known XSS payloads proves
it.

**Architecture:** `SAFE_HTML` is one typed object: the allowed tags, the
attributes per tag and on every tag, the attribute value limits, the address
protocols, the tags removed with their content, and the pipeline's own markup
(SH-5). Two functions derive the `rehype-sanitize` schema and the DOMPurify
configuration from it. The pipeline of this plan (remark with the GitHub
extensions and front matter, `remark-rehype`, `rehype-raw`, the sanitiser,
`rehype-stringify`) runs synchronously and without highlighting; plan 29 adds
blocks, Shiki and the worker around it. The pipeline's own markup is told apart
from the file's by a mark: before `rehype-raw`, every element is the pipeline's,
and each gets an attribute with a random value, new for every run; after it, the
elements that kept the value are the pipeline's, and pipeline-only attributes
are kept only on them. _(Changed while implementing: the plan first told them
apart by source position, but elements that the HTML parser makes up, such as an
unclosed raw `<a data-footnote-ref>` copied into the next paragraph, have no
position, just like the pipeline's footnote list and checkboxes.)_

**Tech Stack:** `unified`, `remark-parse`, `remark-gfm`, `remark-frontmatter`,
`remark-rehype`, `rehype-raw`, `rehype-sanitize`, `rehype-stringify`,
`dompurify` — each installed with `npm install --save-exact` at its current
release; versions recorded in the pull request.

**Spec:** `docs/requirements/preview-html.md` (REQ-EDIT-002: SH-1 to SH-16,
SH-21, SH-22's corpus test, SH-23; criteria 1 to 12 and 17 at the HTML level,
the corpus half of 16); `editor.md` ED-26's Markdown features, ED-29, ED-32;
`docs/architecture/decisions.md` D-7.3, D-7.4, D-7.6; `web-client.md` A-8.12;
`modules.md` A-2.5.

## Global Constraints

- The shared constraints of [the step 2 index](2026-10-28-00-roadmap-step-2.md)
  apply.
- `SAFE_HTML` holds exactly SH-6's tags, SH-9's content-removed tags, SH-11's
  attributes, SH-12's `input` rule, SH-13's value limits (`width`/`height`: a
  whole number or a percentage; `align`: `left`, `center`, `right`, `justify`;
  `valign`: `top`, `middle`, `bottom`, `baseline`; `dir`: `ltr`, `rtl`, `auto`),
  SH-14's `user-content-` prefix and SH-15's protocols (`href`: `http`, `https`,
  `mailto`, relative, fragment; `src`, `srcset`, `cite`: `http`, `https`,
  relative). It lives in
  `libs/web/markdown/src/markdown/whitelist/safe-html.ts`, with a header comment
  saying that a change to it is a security change (SH-2).
- **Pipeline markup** (SH-5), part of `SAFE_HTML` as `PIPELINE_MARKUP`: the
  footnote attributes and IDs that `remark-rehype` produces
  (`data-footnote-ref`, `data-footnote-backref`, `data-footnotes`,
  `aria-describedby`, `aria-label`, `id` on footnote elements), the task-list
  classes (`contains-task-list`, `task-list-item`) and the disabled checkbox.
  They are kept only on elements that carry the pipeline's mark (Architecture).
  Shiki's classes and heading IDs are added after sanitising (plan 29), and
  DOMPurify's configuration allows them by name.
- `remark-rehype` runs with `allowDangerousHtml: true` and `clobberPrefix:
  'user-content-'`. Front matter is parsed and dropped. `.mdx` files go through
  the same pipeline (ED-29).
- **Removal report** (SH-17, SH-18): a map from a removal key to its count.
  Keys: `tag:<name>` for a removed tag (a content-removed tag counts once, its
  content not at all); `attribute:<name>` for a removed attribute or a value
  outside its limits; `address:<scheme>` for an address removed for its protocol
  (`javascript`, `data`, …, lower-case, after decoding). HTML comments are
  removed and not counted (SH-10). The report never holds content or values.
- DOMPurify runs with `RETURN_TRUSTED_TYPE: true`, `SANITIZE_DOM: true`, the
  derived allowed tags and attributes, a URI pattern from the protocols, and
  hooks for the per-tag attributes and value limits.

## Review Focus

- **A raw HTML imitation of the pipeline's markup** (`<a data-footnote-ref
  href="#x">`, `<li class="task-list-item">`, `<input type="checkbox"
  class="task-list-item-checkbox">`) must lose those attributes, while the same
  markup produced from Markdown keeps them → Task 2 test `keeps pipeline markup
  only outside raw HTML`.
- **Addresses obfuscated with entities, mixed case, tabs or newlines inside the
  scheme** (`jav&#x09;ascript:`, `JaVaScRiPt&colon;`) must be removed and
  counted as `address:javascript` → Task 2 test `removes obfuscated addresses`.
- **An HTML block that opens in one paragraph and closes in another**
  (`<details>` … Markdown … `</details>`) must render as one element with the
  Markdown inside, and malformed HTML must not swallow the rest of the file →
  Task 2 test `parses split and malformed HTML as a browser would`.
- **Both steps agreeing**: anything DOMPurify would keep that `rehype-sanitize`
  removed (or the reverse) means the two drifted from the whitelist → Task 1
  test `derives both configurations from the same whitelist`.
- **An `id` already prefixed by the first step** must not become
  `user-content-user-content-…` after DOMPurify → Task 4 test `keeps a single
  user-content- prefix`.

**Files:**

- Create (generated): `libs/web/markdown` (`npx nx g @nx/angular:library
  --directory=libs/web/markdown --name=web-markdown

  --no-interactive`)
- Create: `src/markdown/whitelist/safe-html.ts`,
  `src/markdown/whitelist/derive.ts` (+ `.spec.ts`)

**Interfaces:**

- Produces:
  - `interface SafeHtmlWhitelist { tags: readonly string[]; contentRemovedTags:
    readonly string[]; globalAttributes: readonly string[]; attributes:
    Readonly<Record<string, readonly string[]>>; values: Readonly<Record<string,
    RegExp>>; protocols: Readonly<Record<'href' | 'src' | 'srcset' | 'cite',
    readonly string[]>>; idPrefix: string; pipeline: PipelineMarkup }`;
    `SAFE_HTML: SafeHtmlWhitelist`.
  - `sanitizeSchema(whitelist = SAFE_HTML): Schema` (for `rehype-sanitize`,
    without the pipeline markup, which the plugin of Task 2 adds back);
    `purifyConfig(whitelist = SAFE_HTML): Config` (DOMPurify, with the pipeline
    markup and the names plan 29 adds: `class` values starting with `sk-`,
    heading `id`s starting with the prefix).

### Task 2: The sanitising pipeline

**Files:**

- Create: `src/markdown/pipeline/pipeline-marks.ts`,
  `src/markdown/pipeline/rehype-safe-html.ts`,
  `src/markdown/pipeline/render-safe-html.ts` (each + `.spec.ts`)

**Interfaces:**

- Consumes: Task 1.
- Produces:
  - `pipelineMarks()` — two plugins: `mark`, run right before `rehype-raw`, and
    `find`, run right after it, which sets `data.pipeline` on the pipeline's
    elements and removes the mark from every element.
  - `rehypeSafeHtml` — runs `rehype-sanitize` with `sanitizeSchema()`, then adds
    back the pipeline markup on elements with `data.pipeline`, turns
    protocol-relative addresses into `https:` (SH-16), forces `input` to a
    disabled checkbox or removes it (SH-12), and keeps `language-<name>` as the
    only class of `code` (SH-11).
  - `renderSafeHtml(markdown: string): { html: string; removals: RemovalReport
    }` — the whole pipeline of Global Constraints, synchronous.
