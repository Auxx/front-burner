**Goal:** Plan 82 of [the step 4 index](2026-11-08-00-roadmap-step-4.md):
**Pull** is in the bar, says how it went, refuses plainly when there are
uncommitted changes, and asks about the commit author only when a merge commit
needs one.

**Architecture:** `NetworkJobService` learns one more operation. Waiting saves
go first, inside the service, so that **Pull** from the bar, a banner, a notice
or a retry all do it, and the backend judges what the user sees (ED-17). A
`failed` outcome of `commit-author-not-confirmed` asks through
`CommitAuthorGate` and pulls again, which RC-17's unlock does in the same way.
The two new fixes, `show-changes` and `pull`, connect GA-26's link and GA-30's
button.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/git-advanced.md` (GA-7, GA-8, GA-9, GA-26, GA-27,
GA-28, GA-30's **Pull**, AC-GIT-002.1, AC-GIT-002.9, AC-GIT-002.11);
`docs/requirements/commit-author.md` (CA-14);
`docs/requirements/repo-credentials.md` (AC-REPO-002.2, RC-4's unlock);
`docs/requirements/navigation.md` (NV-9, NV-11, AC-APP-001.5).

## Global Constraints

- The shared constraints of [the step 4 index](2026-11-08-00-roadmap-step-4.md)
  apply.
- **Pull** is offered when the branch has an upstream that is not gone, also
  with nothing to pull, since it fetches first, or has none and
  `GitStatus.sameNameRemote` is true (plan 77). Otherwise it is unavailable,
  with the reason on hover, focus or tap: "This branch has no upstream yet",
  "Make a commit first", "Switch to a branch first" (GA-8).
- A pull is not refused in the client for uncommitted changes, so that its
  message comes from the same place for every client (GA-26); the backend
  answers `409 uncommitted-changes`. The button stays offered.
- Exact messages: toasts "Already up to date" and "Pulled 3 commits" ("Pulled 1
  commit"); the banner "Commit or discard your changes before pulling." with
  **Show changes**. `merge-blocked` says "This pull would overwrite ignored
  files. Move them first.", with the `paths` param as a list, shown as text.
- While it runs: a spinner and "Pulling…". The screen switches to the merge by
  the status alone (plan 81).

## Review Focus

- **Pull pressed just after typing,** from any place: the waiting save goes
  first, and makes the working copy dirty, so the pull is refused rather than
  the edit being lost → Task 1 test `sends a waiting save before pulling, from
  the banner too`.
- **A save that fails before the pull** must stop it and say so → Task 1 test
  `does not pull when a save failed`.
- **"Pull first" on a branch named like a remote branch** must lead to a pull
  that works, and the bar's **Pull** must be offered → Task 2 test (end to end)
  `a branch named like a remote one pulls, then pushes`.
- **The author question cancelled** cancels the pull, with no banner, and the
  fetched counts are shown → Task 1 test `cancelling the author question cancels
  the pull`.
- **An open file changed by the pull** reloads as in ED-24, and with unsaved
  edits asks → Task 2 test (end to end) `reloads the open file after a pull`.
- **"Pull first" while a pull is impossible,** with uncommitted changes, still
  leads to GA-26's message rather than nowhere → Task 2 test `AC-GIT-002.11`,
  with a dirty working copy in a second step.
