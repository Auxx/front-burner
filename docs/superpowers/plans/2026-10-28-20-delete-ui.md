# Delete in the Tree Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 20 of [the step 2 index](2026-10-28-00-roadmap-step-2.md): the
user deletes files, symbolic links and folders from the tree or from the editor
area's message panel, after a confirmation that says what cannot be recovered.
The entry shows "Deleting…" until it is gone, and deleting the open file closes
it.

**Architecture:** In `web/feature-repository-screen`. Plan 19's `entryActions`
gains `delete`, and `EntryCommands` gains its command: it asks plan 17's entry
summary, shows a confirmation built from it, marks the entry as deleting in
`FileTreeStore`, calls plan 18's endpoint and reloads the parent.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/file-browser.md` (REQ-FILE-001: FB-21's **Delete**,
FB-37 to FB-40, FB-45; criteria 18, 19, the web halves of 11 and 26, the delete
half of 23).

## Global Constraints

- The shared constraints of [the step 2 index](2026-10-28-00-roadmap-step-2.md)
  apply.
- **Delete** is offered for files of every kind, symbolic links and folders,
  never for submodules (FB-37); the FB-21 panel offers it on the same terms.
- Delete always asks first (FB-38). English texts _(plan's call, from FB-38)_:
  - title: "Delete {name}?"; buttons **Delete** (danger) and **Cancel**;
  - an uncommitted file: "This file isn't committed, so it can't be recovered.";
  - a folder: "It holds {files, plural, one {# file} other {# files}},
    {nonMarkdown, plural, =0 {none of them non-Markdown} one {# of them
    non-Markdown} other {# of them non-Markdown}}.", and when `uncommitted > 0`:
    "{uncommitted, plural, one {# file isn't committed, so it} other {# files
    aren't committed, so they}} can't be recovered.";
  - a symbolic link: "Only the link is deleted, not what it points to."
- While its request is in flight, the entry shows "Deleting…" in place of its
  actions and cannot be selected (FB-40).
- When the deleted entry is the open file or holds it, the screen goes to
  `/repositories/<id>` and shows FB-12's empty state, not the README; the
  remembered last file is forgotten (FB-39). Dropping a waiting save and its
  browser draft comes with plans 25 and 26.

## Review Focus

- **Deleting the folder that holds the open file** must close the file and show
  the empty state, not reopen the README → Task 2 test `shows the empty state
  after deleting the open file's folder`.
- **The delete failing** (for example a merge started from another device) must
  keep the dialog open with the error and restore the row → Task 2 test
  `restores the row when the delete fails`.
- **The summary request failing** must not let the user delete without a
  confirmation; it shows the error with **Try again** → Task 2 test `does not
  delete without a summary`.
- **Deleting an entry of a folder that is still loading** must not lose the
  "Deleting…" mark when the listing arrives → Task 1 test `keeps the deleting
  mark across a reload`.
- **A folder holding only uncommitted files** must say all of them can't be
  recovered → Task 2 test `counts uncommitted files in the confirmation`.
