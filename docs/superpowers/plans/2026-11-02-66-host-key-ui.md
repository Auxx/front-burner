# Changed Host Key Dialog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 66 of [the step 3 index](2026-11-02-00-roadmap-step-3.md):
**Review the new key** shows both fingerprints behind a strong warning, **Trust
the new key** works only after ticking a checkbox, and the push then runs again.

**Architecture:** One dialog in `web/repository-dialogs`, and one more case in
`CredentialFixesService`. Plan 61's `TrustHostDialog` also takes care of a push
that meets an unknown host, for example after the user's known hosts were lost.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/repo-credentials.md` (RC-4's last row, RC-9, RC-21,
RC-22, RC-25; criterion 12).

## Global Constraints

- The shared constraints of [the step 3 index](2026-11-02-00-roadmap-step-3.md)
  apply.
- The title and first line are exactly "The server's identity has changed. This
  may be an attack.", followed by the explanation that this also happens when a
  provider replaces its keys (RC-21).
- It shows the host and port, and the trusted and the new key, each as key type
  and SHA256 fingerprint. For `github.com` and `bitbucket.org` it links to the
  provider's published fingerprints:
  `https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints`
  and
  `https://support.atlassian.com/bitbucket-cloud/docs/configure-ssh-and-two-step-verification/`.
  Check that both links work when implementing.
- **Trust the new key** is enabled only after the user ticks "I have checked the
  new fingerprint with the server's owner." **Cancel** has the focus and changes
  nothing (RC-22).
- Fingerprints are monospace, wrap anywhere, and can be selected for comparing.
- Without a new key (the probe failed), the dialog says that the server could
  not be reached, with **Try again**, and offers no **Trust** _(plan's call)_.

## Review Focus

- **A host that merely resembles a provider** (`github.com.evil.example`) must
  not get the provider's link → Task 1 test `links only for the exact provider
  hosts`.
- **Reopening the dialog** must start with the checkbox clear → Task 1 test
  `starts with the checkbox clear`.
- **Enter in the dialog** must not trust the key: the default button is
  **Cancel** → Task 1 test `Enter does not trust the key`.
- **A long fingerprint at 320 px** must wrap and stay within the dialog → the
  end-to-end run on a phone.
- **Saving failing** must leave the dialog open with the error, and not run the
  push → Task 2 test `does not run the push again when saving fails`.
