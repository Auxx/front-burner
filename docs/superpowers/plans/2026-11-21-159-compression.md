# Compression Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 159 of [the step 6 index](2026-11-16-00-roadmap-step-6.md), Part
F: fix plan 151's finding, so that NF-2.1, NF-2.2 and NF-2.7 can be met on slow
4G. The instance compresses no response, and it sends the web client's hashed
files with `max-age=0`:

| What                                | As sent | Gzipped | At slow 4G's 180 KB/s |
| ----------------------------------- | ------- | ------- | --------------------- |
| The first page's files              | 714 KB  | 198 KB  | 4.0 s → 1.1 s         |
| `main-*.js` alone                   | 491 KB  | 128 KB  | 2.7 s → 0.7 s         |
| The listing of a 1,000-entry folder | 94 KB   | 3 KB    | 0.52 s → 0.02 s       |
| A warm reload (one 304 per file)    | —       | —       | 3.6 s of round trips  |

After this plan, the instance sends the web client's files compressed at build
time, compresses API responses as it sends them, and lets the browser keep every
hashed file for good. Plan 151's tool is run again and the checklist updated.

**Architecture:**

- **The web client's files are compressed once, at build** _(plan's call: a 2
  vCPU reference host should not compress 500 KB of JavaScript on every cold
  load, and Brotli's best quality is too slow to run per request)_. A new target
  `web:precompress`, which depends on `web:build`, writes `<file>.br` (Brotli,
  quality 11) and `<file>.gz` (gzip, level 9) next to every file of
  `dist/apps/web/browser` that is worth it: `.js`, `.css`, `.json`, `.svg`,
  `.txt`, `.webmanifest` and `.map` if any, of 1 KB or more, kept only when
  smaller than the original. `index.html` is left out: it is a template that the
  server fills with a nonce per request (A-7.9). The script is
  `apps/web/scripts/precompress.mjs`, next to `size-check.mjs`, with Node's
  `zlib` only. The Dockerfile runs it after `web:build:production`; CI's image
  job gets it with the Dockerfile.
- **`serveWebClient` picks the variant** (A-7.9): for a GET or HEAD of a file
  that has a `.br` or `.gz` next to it, it sends the best one that the request's
  `Accept-Encoding` allows (`br`, then `gzip`, with `q=0` honoured), with the
  original's `Content-Type`, `Content-Encoding`, and `Vary: Accept-Encoding` on
  every answer for such a file, compressed or not. A compressed answer does not
  take `Range` requests _(plan's call: nothing in the web client asks for
  ranges, and a range of compressed bytes is a trap)_. The `.br` and `.gz` files
  themselves are not served by their own names: a request for `main-X.js.br`
  gets 404, so that no second URL serves the same content with the wrong type.
- **Hashed files are cached for good** (A-7.9): `Cache-Control: public,
  max-age=31536000, immutable` for every file that the build names by its
  content, which with `outputHashing: "all"` is every root-level `.js` and
  `.css` file (`main-*`, `chunk-*`, `worker-chunk-*`, `polyfills-*`, `styles-*`)
  and every file in `media/`. `index.html` stays `no-store`; `assets/` and
  `i18n/` keep `max-age=0`, as their names do not change with their content;
  `?v=<version>` keeps working as now. The rule is a list of places, not a guess
  from the name, and `precompress.mjs` checks it: it fails the build when a
  root-level `.js` or `.css` file or a file in `media/` has no hash in its name
  (`-` and 8 letters, digits, `_` or `-` before the extension), so that a change
  of Angular's naming is caught before an unhashed file is cached for a year.
- **API responses are compressed as they are sent** by the `compression`
  middleware (Express's own, `1.8.2`, made a direct, pinned dependency, with
  `@types/compression` as a dev dependency), registered in `start-server.ts`
  before the routes _(plan's call: it is the standard Express middleware, small,
  and already in the tree through the dev server; writing our own would be more
  code to review for no gain)_. Settings: compressible types only (its default
  filter), at least 1 KB (its default), gzip at level 6 and Brotli at quality 4
  when the client prefers it _(plan's call: cheap on the CPU, and most of the
  gain on JSON)_. Left out, by a filter in front of the default:
  - **the push channel** (`text/event-stream`, A-3.10), which must reach the
    client event by event and would be held in the compressor's buffer;
  - **the authentication and onboarding routes** (`/api/v1/auth/` and
    `/api/v1/onboarding/`), whose answers carry auth tokens: with a secret and
    something the request chose in the same compressed body, the body's size can
    leak the secret (BREACH) _(plan's call: these answers are small, so nothing
    is lost)_;
  - anything the web client's handler already answered (it sets its own
    encoding).
- **`Server-Timing` keeps its meaning** (A-7.14): it is set before the body is
  written, so `app;dur` still leaves out the time to compress and send.
  `perf-api.mjs`'s numbers stay comparable with plan 150's.
- **The deployment guide** says that the instance compresses its responses
  itself, so the HTTPS terminator need not (Caddy's `encode` is not needed, and
  Caddy does not compress again what arrives compressed).

**Tech Stack:** Express, `compression` 1.8.2, Node's `zlib`; Vitest; the
server-e2e suite; `perf-screen.mjs` and `perf-api.mjs` (plans 150 and 151).

**Spec:** `docs/architecture/non-functional.md` NF-2.1, NF-2.2, NF-2.7, NF-2.9;
`docs/architecture/security.md` A-7.9, A-7.14; `docs/wiki/release-checks.md`,
"Plan 151: indicative screen timings".

## Global Constraints

- The shared constraints of [the step 6 index](2026-11-16-00-roadmap-step-6.md)
  apply.
- No new variable: compression and caching are always on. Nothing an operator
  would turn off, and A-1.15's list stays as it is.
- The new runtime dependency is pinned to an exact version in the root
  `package.json`, like every other; the image's Trivy scan (NF-11.10) and SBOM
  (NF-11.12) pick it up with no change.
- NF-2.9's `size-check` keeps measuring gzipped sizes from the uncompressed
  files; it does not read the `.gz` files.
- A-7.9 and a new **A-7.15** (compression, its exclusions and why) in
  `security.md` are updated in the same pull request.

## Review Focus

- **The push channel buffered** by the compressor → events arrive late or in
  bursts: the server-e2e test reads one event as it is sent, with `Accept-
  Encoding: gzip, br` on the request.
- **An auth token in a compressed body** (BREACH) → the exclusion is by path
  prefix, tested on the login, refresh, OIDC exchange and onboarding answers.
- **An unhashed file cached for a year** → the cache rule is by place, and the
  build fails when a file in those places has no hash.
- **The wrong `Content-Type` on a compressed file** (`application/x-gzip` for
  `main-X.js`) → tests check the type, the encoding and `Vary`.
- **A `.br` URL served by its own name** → 404, tested.
- **`index.html` precompressed** by mistake → it would lose its nonce; the
  script leaves it out by name, tested.

## Left out

- **HTTP/2 or HTTP/3**: the instance speaks HTTP/1.1, and the HTTPS terminator
  in front of it may speak HTTP/2 to browsers already; NF-2's numbers are taken
  without one.
- **`modulepreload` for the lazy route's and the editor's chunks**, which would
  cut the waterfall of round trips: measured in Task 4 first, a plan of its own
  if needed.
- **Compressing request bodies** (saves): NF-2.3 is measured on the server and
  passes; the upload side of slow 4G is not one of the missed rows.
