# Code Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 24 of [the step 2 index](2026-10-28-00-roadmap-step-2.md): a
`web/code-editor` library wraps CodeMirror 6 as the editor that the repository
screen (plan 25) and, later, the conflict views use: Markdown and front matter
highlighting that can be switched off and on (ED-9a), soft wrap, spell check,
find and replace, right-to-left lines, and one editor state per file so that
each file keeps its undo history.

**Architecture:** A new `type:domain` library (A-2.5) with two parts. Pure
functions build an `EditorState` from a file's text with exactly the extensions
A-8.11 lists, and switch highlighting and read-only through `Compartment`s. One
component owns the `EditorView`, shows whatever state it is given with
`view.setState`, and reports every transaction's new state, so that the caller
keeps the state per file (A-8.15, ED-8). The CodeMirror theme uses the `ui`
library's `--ui-syntax-*` tokens through CSS classes, never inline styles, and
CodeMirror's own style element gets the page's CSP nonce (NF-11.1).

**Tech Stack:** CodeMirror 6 (`@codemirror/state`, `view`, `language`,
`commands`, `search`, `lang-markdown`, `lang-yaml`, installed with the typing
check), `@lezer/highlight` (`classHighlighter`, add it with `npm install
--save-exact`).

**Spec:** `docs/requirements/editor.md` (REQ-EDIT-001: ED-4, ED-8 to ED-15,
ED-37, ED-39 for the editor; ED-9a's mechanism);
`docs/architecture/web-client.md` A-8.11; `modules.md` A-2.4, A-2.5;
`docs/architecture/spikes.md` spike 3; `design-system.md` A-10.14 (syntax
colours).

## Global Constraints

- The shared constraints of [the step 2 index](2026-10-28-00-roadmap-step-2.md)
  apply.
- **No `basicSetup`.** The extensions are exactly: `history`, `drawSelection`,
  `search({ top: true })`, the keymaps `defaultKeymap`, `historyKeymap`,
  `searchKeymap` and `indentWithTab`, the highlighting compartment,
  `syntaxHighlighting(classHighlighter)`, `EditorView.lineWrapping`,
  `EditorView.perLineTextDirection.of(true)`, content attributes
  `spellcheck="true" autocorrect="on" autocapitalize="sentences"`, the read-only
  compartment (`EditorState.readOnly` and `EditorView.editable`),
  `EditorView.cspNonce`, and the theme. Nothing that changes the text on its
  own: no bracket closing, no list continuation, no autocompletion (ED-9). This
  is the setup that spike 3 measured on a real phone; adding an extension means
  measuring again with the `typing-test` tool.
- **The highlighting compartment** holds `yamlFrontmatter({ content: markdown({
  codeLanguages: [], addKeymap: false }) })` when highlighting is on and nothing
  when it is off. Switching it never recreates the state, so the undo history
  stays (ED-8, ED-9a).
- `Tab` inserts a tab; `Esc` then `Tab` moves the focus out, as CodeMirror's
  tab-focus mode does with `indentWithTab` (ED-11, NF-13.3).
- The editor's accessible name is the open file's name (ED-37): `aria-label` on
  the content element.
- The library is imported only from code that is itself loaded lazily (ED-4,
  NF-2.9); `apps/web`'s initial bundle must not grow.
- Its lazy chunk size is measured and recorded in A-8.11 by plan 25, the first
  plan that loads it from a route.

## Review Focus

- **Turning highlighting on in a file with edits** must keep the undo history:
  undo after the switch still undoes the last edit → Task 1 test `keeps the undo
  history when highlighting is switched`.
- **Switching between two files and back** must restore each file's own undo
  history and cursor → Task 2 test `AC-EDIT-001.23: undoes the first file's edit
  after switching back`.
- **A state given while the view is focused** (the file switched while typing)
  must not throw or lose the new state's selection → Task 2 test `shows a new
  state while focused`.
- **The CSP nonce** must reach CodeMirror's injected style element, or the
  editor is unstyled under the real policy → Task 2 test `passes the CSP nonce
  to CodeMirror`.
- **Typing a bracket, a list marker and Enter after a list item** must insert
  exactly what was typed → Task 1 test `changes nothing on its own`.

### Task 1: The editor state

**Files:**

- Create (generated): `libs/web/code-editor` (`npx nx g @nx/angular:library
  --directory=libs/web/code-editor --name=web-code-editor
  --importPath=@front-burner/web-code-editor --prefix=ce
  --unitTestRunner=vitest-angular --tags=scope:web,type:domain
  --no-interactive`)
- Create: `src/code-editor/state/editor-state.ts` (+ `.spec.ts`)

**Interfaces:**

- Produces:
  - `interface EditorStateOptions { content: string; highlight: boolean;
    readOnly?: boolean; label: string; nonce?: string }`.
  - `createEditorState(options: EditorStateOptions): EditorState` — the
    extensions of Global Constraints.
  - `setHighlighting(state: EditorState, on: boolean): TransactionSpec` and
    `setReadOnly(state: EditorState, on: boolean): TransactionSpec` —
    compartment reconfigurations; `isHighlighting(state: EditorState): boolean`.
  - `contentOf(state: EditorState): string` — the text with `\n` line breaks
    (plan 23's codec adds the file's line ending back).

### Task 2: The editor component and theme

**Files:**

- Create (generated component): `src/code-editor/components/code-editor` (+
  `.spec.ts`)
- Create: `src/code-editor/theme/editor-theme.ts`,
  `src/code-editor/components/code-editor/code-editor.component.scss` (the
  `tok-*` classes on `--ui-syntax-*` tokens)
- Modify: `libs/web/code-editor/src/index.ts`

**Interfaces:**

- Consumes: Task 1; Angular's `CSP_NONCE` token.
- Produces:
  - `interface EditorStateChange { state: EditorState; docChanged: boolean }`.
  - `CodeEditorComponent` (`ce-code-editor`): input `state: EditorState`
    (required) — a new value is shown with `view.setState`, unless it is the
    state the view already has; output `stateChange: EditorStateChange` after
    every transaction; methods `openSearch(): void` (the find and replace panel,
    ED-11), `focus(): void`, `scrollToLine(line: number): void`, `topLine():
    number` (the first visible line, for plans 30 and 31). The view is destroyed
    with the component.
  - The theme: the editor fills its container, uses the `ui` fonts and colours
    in both colour schemes (ED-14), and keeps the cursor in view when the visual
    viewport shrinks for the on-screen keyboard (ED-15: `scrollIntoView` of the
    selection on `visualViewport` `resize`).

- [ ] **Step 1: Write the failing tests**: `shows the given state`;
      `AC-EDIT-001.23: undoes the first file's edit after switching back` (two
      states swapped through the input); `shows a new state while focused`;
      `emits each transaction's state`; `opens the search panel`; `passes the
      CSP nonce to CodeMirror`; `labels the editor with the file name`; `uses
      classes, not inline colours, for tokens`.
- [ ] **Step 2: Run them and see them fail** — `npx nx test web-code-editor`.
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run them and see them pass** — same command.
- [ ] **Step 5: Commit** — `feat(code-editor): add the editor component`
