# Orphaned Working Copies Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or

> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 128 of [the step 6 index](2026-11-16-00-roadmap-step-6.md): on
start, a working copy that no repository in the database owns is moved to
`orphans/` and logged, never deleted (NF-6.4). This is what keeps a restore of
an older database from losing the unpushed work of newer repositories.

**Architecture:** A start-up step in `server/feature/repositories`,
`OrphanedWorkingCopies`, runs in `onModuleInit` before `WorkingCopyRecovery`
(which only reads repositories that exist). It walks `repos/<user-id>/<repo-id>`
one level per ID and compares with every repository row of every user
(`InstanceRepositories`). An orphan moves with one `rename` to
`orphans/<user-id>-<repo-id>-<UTC time>` _(plan's call: the time keeps a second
orphan of the same IDs apart)_. An empty `<user-id>` folder left behind is
removed. The other half of NF-6.4, a repository whose working copy is missing,
is already RM-6's start check.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/architecture/non-functional.md` NF-6.4, NF-5.1, NF-5.2;
`docs/requirements/repo-manage.md` RM-6.

## Global Constraints

- The shared constraints of [the step 6 index](2026-11-16-00-roadmap-step-6.md)
  apply.
- Nothing is ever deleted except an empty user folder. A name that is not a
  number at either level is left where it is and logged at `warn`: the backend
  did not make it.
- The log line names the IDs and the new folder name, never repository names
  (NF-10.5): `Working copy of repository 12 (user 3) has no repository; moved to
  orphans/3-12-2026-11-16T10-00-00Z`.
- A repository that is cloning has its copy in `tmp/` (emptied on start), so it
  is not an orphan concern; one that is `error` with a working copy keeps it.

## Review Focus

- **A database restored from an older snapshot** next to newer working copies →
  test `moves a working copy without a repository to orphans`.
- **Another user's row with the same repository ID** never saves an orphan: the
  pair `(user, repository)` must match → test `a working copy under the wrong
  user is an orphan`.
- **A move that fails** (for example `orphans/` not writable) is logged and does
  not stop the start or the other moves → test `a failed move is logged and the
  start goes on`.
