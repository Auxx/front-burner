# Push Button Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 58 of [the step 3 index](2026-11-02-00-roadmap-step-3.md):
**Push** is in the bar, shows progress, says "Pushed 2 commits to origin/main",
and says plainly why a push failed.

**Architecture:** A page-provided `PushService` follows one job: it starts it,
or takes it up from `GitStatus.networkJob` after a reload or from another tab,
and reads `GitJobState` on `job.finished` and on every (re)connect. A failure
becomes a `problem` signal shown in a banner below the bar. `pushProblem(code)`
is the one table from code to message and fix (RC-4), and plans 60, 63, 64 and
66 connect the fix buttons; until then the message shows without a button.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/git-advanced.md` (GA-3, GA-7's **Push**, GA-8,
GA-9, GA-30 to GA-32, GA-43); `docs/requirements/repo-credentials.md` (RC-4's
messages); `docs/requirements/navigation.md` (NV-9, NV-11, NV-16).

## Global Constraints

- The shared constraints of [the step 3 index](2026-11-02-00-roadmap-step-3.md)
  apply.
- **Push** is offered when `ahead > 0`, or the branch is unpublished and has
  commits. Otherwise it is disabled, with the reason available on hover, focus
  or tap: "Nothing to push", or "Make a commit first" (GA-8). On narrow screens
  it is in a menu (GA-7).
- While a push runs, the button shows a spinner and "Pushing…" (GA-9), and the
  status says so to screen readers.
- Exact messages: "Pushed 2 commits to origin/main" (a toast, as
  `DiskChangesService` shows; GA-32), "The remote has new commits. Pull first."
  (GA-30), and the five rows of RC-4's table. A rejection in other words shows
  the remote's messages in a `<pre>`, as text, with **Try again** where the
  cause is the network or the server (GA-31, GA-43).
- `pushProblem(code)` returns `{ messageKey: string; fix: 'add-credentials' |
  'fix-credentials' | 'other-credentials' | 'unlock' | 'review-host-key' |
  'trust-host' | 'retry' | null }`.

## Review Focus

- **A `job.finished` missed while offline** must still end the spinner → Task 1
  test `reads the job again after a reconnect`.
- **A reload during a push** must show it still running, and its result → Task 1
  test `takes up a running push from the status`.
- **Another tab's push** disables **Push** here, and does not show this tab a
  failure it did not ask for → Task 1 test `shows another tab's push as running,
  and its failure only quietly`. Only the tab that started a push shows its
  toast.
- **HTML in a server hook's message** must show as text → Task 2 test `shows the
  remote's lines as text`.
- **A push pressed with a waiting save** pushes only what was committed, as
  always; no save is flushed → Task 2 test `does not flush saves`.
