# Diff View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 49 of [the step 3 index](2026-11-02-00-roadmap-step-3.md):
selecting an entry in **Changes** shows its unified diff in the editor area,
with changed words highlighted, folded unchanged parts and **Open in editor**.

**Architecture:** A pure `foldDiff` turns the API's lines into rows and folds,
and a pure `changedWords` marks changed words in a removed and added pair of
lines, so both are tested without a browser. The view is a new component that
replaces the editor while a diff is selected; opening a file ends the diff. The
selected path lives in the page, not in the URL _(plan's call: the URL keeps
naming the open file, so that a reload opens the file)_.

**Tech Stack:** adds `diff` (jsdiff) with `npm install --save-exact diff`, for
`diffWordsWithSpace`.

**Spec:** `docs/requirements/git-advanced.md` (GA-14 to GA-16, criteria 3 and
22); `docs/architecture/non-functional.md` NF-13.7, NF-12.4.

## Global Constraints

- The shared constraints of [the step 3 index](2026-11-02-00-roadmap-step-3.md)
  apply.
- Unchanged runs longer than 8 lines are folded, keeping 3 lines of context on
  each side _(plan's call: "a few lines", GA-14)_. A fold says "Show 42 more
  lines" and opens in place. When the response has `complete: false`, a fold is
  not a button.
- Exact texts: "Binary file changed" with the old and new size, "This diff is
  too large to show", and "Only the line endings changed" _(plan's call on the
  wording; GA-16 asks that it says so)_.
- A trailing `\r` is shown as a visible `␍` mark, so that line ending changes
  can be seen (GA-16).
- **Open in editor** is offered for a Markdown file that exists (GA-15).
- Added and removed lines also have a `+` and `-` sign, and word highlights also
  have an underline or `<mark>`, so that colour is not the only signal
  (NF-13.7). Lines are text, escaped by Angular's binding. Never `innerHTML`.
- `changedWords` is skipped for a line over 2,000 characters, or a run of over
  500 lines; these show as whole-line changes _(plan's call: jsdiff is slow on
  long input)_.

## Review Focus

- **Markup in a line** (`<img onerror=…>`) must show as text → Task 2 test
  `shows HTML in a line as text`.
- **A long line on a phone** must scroll inside the diff, and not the page →
  Task 2 test `scrolls long lines inside the diff` and the end-to-end run at 320
  px.
- **A changed file that was committed elsewhere while its diff is open** must
  not show stale lines or an error → Task 2 test `reloads the diff on
  git.changed and says when there are no more changes`.
- **Fast selection of several entries,** where an older response arrives last,
  must show the last one selected → Task 2 test `shows the diff of the last
  selection`.
- **A file with 20,000 changed lines** must not freeze the tab → Task 1 test
  `skips word highlighting for long runs`.
