# Repository Screen Layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 37 of [the design pass index](2026-10-30-00-design-pass.md): the
repository screen looks like an IDE. An activity bar on the canvas holds the
**Files** toggle (a folder icon); the file tree and the editor are two islands;
the editor toolbar has Find on the left and the view modes on the right, with a
2 px canvas-coloured line under it that meets an equally thin, straight line
between editor and preview. The screen builds one app shell for all its states.

**Architecture:** `web/feature-repository-screen` only, plus a component token
in `ui-split-pane`. The page keeps `PaneMemoryService` and `drawerOpen`; the
activity bar's `selected` is derived from them and writes back through the
existing `toggleFiles`.

**Tech Stack:** as plan 35.

**Spec:** [design](../specs/2026-10-30-islands-design-pass-design.md) Per page:
Repository screen (Layout, Editor toolbar, Editor / preview split, States other
than "ready"), Shared layouts 5. FB-7 to FB-10, NV-9, NV-11, A-10.5, A-10.6.

## Global Constraints

- The shared constraints of [the index](2026-10-30-00-design-pass.md) apply.
- Activity bar: `ui-activity-bar` with `label` "Tool windows" _(plan's call; key
  `web-feature-repository-screen.RepositoryScreenPage.toolWindows`)_, one item
  `uiActivityBarItem="files"`, `label` "Files", icon **`folder`**; `orientation`
  vertical on wide screens, horizontal on narrow (A-10.6, `shell.narrow()`).
- Islands: the file tree in `ui-island` (`label` "Files", `scrollable="false"`);
  the editor area in `ui-island` (`scrollable="false"`); gap `--ui-island-gap`
  (8 px, plan 35).
- Editor toolbar: Find **start**, view modes **end**; under it a **2 px** line
  in `--ui-surface-canvas` across the island.
- Editor/preview separator: a **2 px** straight line in `--ui-surface-canvas`,
  no radius; still draggable and keyboard-resizable with the same ≥ 24 px target
  (NF-13.5).
- States: **loading** spinner as today; **missing** and **failed**: app shell
  with `shell-app-header`, no activity bar, content in `ui-centred-island`
  (`24rem`); **not-openable**: app shell with `rs-repository-bar`
  (`withFiles=false`), no activity bar, `rs-not-openable` in `ui-centred-island`
  (`28rem`). No title bar on this screen; its `h1` stays in the repository
  switcher.

## Review Focus

- **Collapsing the tree, reloading, and opening the screen again** keeps it
  collapsed (FB-8 memory) and the activity bar item shows unpressed (Task 2 test
  with `localStorage` `fb.<id>.repositoryScreen.sideOpen = false`).
- **On a narrow screen, opening a file from the drawer** closes the drawer and
  unpresses the item (FB-9; Task 2 test).
- **Crossing the breakpoint with the drawer open** (rotating a phone) leaves the
  item consistent with the closed drawer (Task 2 test with the narrow signal
  flipped).
- **Dragging the 2 px separator** still works with the pointer and the keyboard
  (Task 4 e2e: arrow keys on the separator change the editor's width).
- **The screen at 320 px** in Edit and Preview tabs keeps the toolbar on one row
  or wraps without sideways scroll (Task 4 screenshot).
