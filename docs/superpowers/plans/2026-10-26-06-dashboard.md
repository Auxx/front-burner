# Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 6 of [the index](2026-10-26-00-roadmap.md): after logging in, the
user sees the dashboard: the guide to adding a repository (full or compact) and
up to 10 of their repositories by last access time, each with its remote, "Last
accessed" and its status.

**Architecture:** The `repositories` table arrives with the columns REQ-REPO-001
sets, except the credentials reference, which plan 11 adds. A new
`server/feature/repositories` library answers the recent list, ordered and
limited by the backend (DS-4, DS-17). Remote URL parsing and the "host/path"
form come from plan 3's `shared/util` helpers. The dashboard page in
`web/feature-dashboard` (from plan 2) is built from `ui` components. Live status
updates (DS-23) come with the push channel in plan 12.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/dashboard.md` (REQ-DASH-001: DS-1 to DS-6, DS-9 to
DS-22, DS-24 to DS-26; criteria 1 to 5, 7 to 10, 13, 15, 16);
`docs/requirements/repo-manage.md` RM-6, RM-8 (the status and warning labels);
`docs/requirements/navigation.md` NV-13. Architecture: `data.md` A-4.4, A-4.5b;
`security.md` A-7.3; `modules.md` A-2.

## Global Constraints

- The shared constraints of [the index](2026-10-26-00-roadmap.md) apply.
- Plan 2's `authGuard`, `CurrentUserService`, `web-feature-dashboard` and its
  `DashboardPage` (with its `h1` "Dashboard") are extended, not replaced.
- Every query filters by `req.auth.userId`; no route returns another user's
  repository (DS-3, A-7.3).
- The guide's texts are exactly DS-11's and DS-12's; one set of keys serves the
  full guide and **How it works** (DS-13). Status and warning labels are RM-6's
  and RM-8's.
- Until plans 11 and 12 and REQ-REPO-003 are built, **Add repository**
  (`/repositories/new`), **All repositories** (`/repositories`), an openable
  entry (`/repositories/<id>`) and the settings link
  (`/repositories/<id>/settings`) lead to "Page not found". The links are right
  now; the pages come later.

## Review Focus

- **A stored remote URL with a user name or token in it** (from a database
  edited by hand, or an older version) must be shown without them (DS-19) → plan
  3's Task 6 test `drops credentials from the display form` and Task 5 test
  `criterion 10`.
- **Two repositories with the same last access time** must come in name order,
  ignoring case, and the order must not change between loads → Task 3 test
  `orders ties by name ignoring case`.
- **A repository that is still cloning or failed**, clicked or opened with the
  keyboard, must not lead to the editor, and must offer its settings instead
  (DS-22) → Task 4 test `does not link a cloning repository to the editor and
  offers its settings`.
- **`localStorage` that throws** (Safari private mode, storage disabled) must
  not break the dashboard: the full guide shows until the list loads (DS-25) →
  Task 4 test `works without localStorage`.
- **The list failing to load** must leave **Add repository** usable and show
  **Try again**, which loads again without a page reload (DS-26) → Task 4 test
  `shows the error with Try again`.

**Files:**

- Create: `libs/server/core/database/src/schema/repositories.ts`
- Modify: `schema/index.ts` (+ `schema.spec.ts`)
- Create (generated):
  `libs/server/core/database/migrations/0004_repositories.sql`

**Interfaces:**

- Produces:
  - `CLONE_MODES = ['full', 'single-branch']`, `GIT_LEVELS = ['simple',
    'guided', 'advanced']`, `REPOSITORY_STATUS_VALUES = ['cloning', 'ready',
    'error']`, `REPOSITORY_ERROR_VALUES = ['clone-failed', 'clone-timed-out',
    'working-copy-missing']` (each `satisfies` the contracts' type, as
    `ONBOARDING_STATE_VALUES` does).
  - `repositories`: `id` integer primary key autoincrement; `userId` (`user_id`)
    not null, references `users.id` `ON DELETE CASCADE`; `name` text not null;
    `remoteUrl` (`remote_url`) text not null; `cloneMode` (`clone_mode`);
    `branch` text nullable (single branch only); `gitLevel` (`git_level`);
    `status`; `errorCode` (`error_code`) nullable; `createdAt`, `lastAccessedAt`
    (`last_accessed_at`) `timestamp_ms` not null. Unique index
    `repositories_user_name_unique` on `(user_id, lower(name))` (AR-15); index
    on `(user_id, last_accessed_at)`. Types `Repository`, `NewRepository`.
  - "Needs your confirmation" is not stored: adding on a user's behalf is not in
    the MVP (DS, MVP notes).

      in case for one user`; `allows the same name for two users`; `deletes a

### Task 4: The dashboard page

**Files:**

- Create (generated components in feature `dashboard` of
  `web-feature-dashboard`): `add-repository-guide`, `recent-repositories`,
  `repository-entry` (each + `.spec.ts`)
- Create (generated service): `dashboard-hint` (`DS-25`'s remembered guide form)
- Create: `libs/web/core/src/core/utils/relative-time/relative-time.ts` (+
  `.spec.ts`), exported from `web-core`'s main entry
- Modify: `dashboard.page.*`, `apps/web/public/i18n/en.json`

**Interfaces:**

- Consumes: `RepositoriesApi.recent()`, `CurrentUserService.user()`, `ui`'s
  `ButtonComponent`, `BadgeComponent`, `SpinnerComponent`,
  `InlineBannerComponent`, `TooltipDirective`, `IconComponent`.
- Produces:
  - `relativeTime(date: Date, now: Date, locale: string): string` —
    `Intl.RelativeTimeFormat(locale, { numeric: 'auto' })` with the largest unit
    of second, minute, hour, day, month, year that fits, rounded down ("3 hours
    ago", "yesterday") _(plan's call)_.
  - `DashboardHintService`: `hadRepositories(userId): boolean`,
    `remember(userId, has: boolean)` — `localStorage` key
    `front-burner.dashboard.has-repositories.<userId>`; every access in
    `try`/`catch`, a failure reads as `false` (DS-25).
  - `AddRepositoryGuideComponent`, input `form: 'full' | 'compact'`: the full
    guide of DS-11 (heading "Add your first repository", explanation, three
    numbered steps, **Add repository**); the compact strip of DS-12 ("Add
    another repository from an HTTPS or SSH URL", **How it works** as a
    disclosure button with `aria-expanded` that shows the same explanation and
    steps in place, DS-13, and **Add repository**, below the text under 600 px).
    **Add repository** is a link-button to `/repositories/new` (DS-14).
  - `RepositoryEntryComponent`, input `repository: RepositorySummary`: name;
    remote; "Last accessed" and `relativeTime`, with the exact date and time
    (`Intl.DateTimeFormat`, `dateStyle: 'medium'`, `timeStyle: 'short'`) in a
    `uiTooltip`; for `ready`, the name is a link to `/repositories/<id>`
    (DS-20); for `cloning` and `error`, a badge with the status, for `error` its
    label (RM-6), no link to the editor, and a **Settings** link to
    `/repositories/<id>/settings` (DS-22); warnings as badges (RM-8, DS-18);
    `needs-confirmation` as a highlighted badge (DS-21; its flow is not built).
  - `RecentRepositoriesComponent`: the heading "Recent repositories", the list,
    and **All repositories** to `/repositories` (DS-15, DS-24).
  - `DashboardPage`: the guide first, shown at once (DS-10) — compact when the
    list has entries, otherwise full; before the list has loaded, the hint
    decides (DS-25). Then the recent section: a spinner while loading; on
    failure "Your repositories could not be loaded" with **Try again** (DS-26);
    nothing when the list is empty (DS-15). After a load it calls `remember`.

- [ ] **Step 1: Write the failing tests**: `relativeTime` (`2 hours 59 minutes`
