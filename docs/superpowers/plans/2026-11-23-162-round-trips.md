> superpowers:subagent-driven-development (recommended) or

**Goal:** Plan 162 of [the step 6 index](2026-11-16-00-roadmap-step-6.md), Part
F: after plan 159's compression, two slow 4G rows still miss
(`docs/wiki/release-checks.md`, "Plan 159: after compression"):

| Row                           | After plan 159 (p95)           | Target |
| ----------------------------- | ------------------------------ | ------ |
| NF-2.7 First load, cold cache | 5.4 s (desktop), 5.6 s (phone) | 5 s    |
| NF-2.2 Editor usable, 100 KB  | 3.4 s (desktop), 3.6 s (phone) | 2 s    |

The bytes are no longer the problem: the first page's 167 KB take about 1 s at
180 KB/s. What is left is requests that start one after another, each costing
slow 4G's 562.5 ms round trip. Read from the code and the build, the chains are:

- **First load of `/`:** `index.html` → `main-*.js` and its preloads → the
  router finds the dashboard's lazy chunk, then the onboarding guard asks `GET
  /api/v1/onboarding`, then the shell's lazy component loads, and the first
  translated template asks for `i18n/en.json`. A lazy chunk's own static imports
  are found only once it has arrived, a round trip per level.
- **Opening a Markdown file:** `GET …/file` → only when it has arrived does the
  `@defer` around `rs-editor-pane` (`editor-area.component.html`) start to load
  CodeMirror's chunk → then that chunk's static imports, level by level.

After this plan, every request that can be known at the start is started at the
start: the server preloads the first route's chunks in `index.html`, the
translations and the onboarding status are asked for at once, and the editor's
chunks load while the file does. Plan 151's tool is run again and the checklist
updated.

**Architecture:**

- **Measure the chain first.** `perf-screen.mjs` gets a `waterfall` command that
  records every request of a first load and of opening `big.md` on slow 4G, with
  when it started and ended, and groups them into **waves**: a request is in
  wave _n_ + 1 when it starts after a request of wave _n_ has ended and before
  any other has. The number of waves is the number of round trips one after
  another, so each task below is checked by the waves it removes, not only by
  the end time. The baseline goes into the checklist before any fix.
- **A chunk map, written at build** _(plan's call: the build is the only place
  that knows which file holds which lazy import; guessing from the source or
  reading the chunks' text would break on Angular's next naming change)_. The
  production build sets `statsJson: true`, which writes
  `dist/apps/web/browser-stats.json` (esbuild's metafile). A new script
  `apps/web/scripts/chunk-map.mjs`, next to `precompress.mjs` and run before it,
  writes `dist/apps/web/chunk-map.json`: for each **group**, the files to
  preload, which are the output chunk whose `entryPoint` is the group's source
  file plus every chunk it imports statically, transitively, less the files
  `index.html` already loads. It fails the build when a group's source file is
  in no output's `entryPoint`, or a listed file is missing from `browser/`. The
  file sits next to `browser/`, not in it, so it is not served.

  | Group               | Source file (`entryPoint`)                                                                                 |
  | ------------------- | ---------------------------------------------------------------------------------------------------------- |
  | `auth`              | `libs/web/feature-auth/src/index.ts`                                                                       |
  | `shell`             | `libs/web/shell/src/index.ts`                                                                              |
  | `dashboard`         | `libs/web/feature-dashboard/src/index.ts`                                                                  |
  | `repositories`      | `libs/web/feature-repositories/src/index.ts`                                                               |
  | `preferences`       | `libs/web/feature-preferences/src/index.ts`                                                                |
  | `repository-screen` | `libs/web/feature-repository-screen/src/index.ts`                                                          |
  | `editor`            | `libs/web/feature-repository-screen/src/repository-screen/components/editor-pane/editor-pane.component.ts` |

- **The server preloads the first route's chunks** (A-7.9). `serveWebClient`
  reads `chunk-map.json` at startup (none: no preloads, as now) and, as it fills
  `index.html`'s nonce, adds `<link rel="modulepreload" href="…" nonce="…">` for
  the groups of the requested path, before `</head>`:

  | Path                                                                  | Groups                        |
  | --------------------------------------------------------------------- | ----------------------------- |
  | `/`                                                                   | `shell`, `dashboard`          |
  | `/repositories`                                                       | `shell`, `repositories`       |
  | `/preferences`                                                        | `shell`, `preferences`        |
  | `/repositories/<id>` and anything below it                            | `repository-screen`           |
  | `/repositories/<id>/files/<…>.md` (and `.markdown`, `.mdx`, any case) | `repository-screen`, `editor` |
  | `/login`, `/login/…`, `/onboarding`                                   | `auth`                        |
  | anything else                                                         | none                          |

  The match is on the decoded, normalised path, case-insensitive like Express's
  routing; a wrong guess only costs bytes, never breaks the page. Every page
  also gets `<link rel="preload" href="i18n/en.json" as="fetch"
  crossorigin="anonymous" nonce="…">` _(plan's call: the only language is
  English, NF-14; with more languages this picks the one the client will ask
  for)_. `crossorigin="anonymous"` matches the web client's same-origin `fetch`,
  so the browser reuses the preloaded answer; the waterfall proves it with one
  `en.json` request, not two.
- **NF-2.9 is unchanged** _(plan's call)_: `size-check` keeps measuring the
  built `index.html`, which this plan does not change. The server's preloads are
  the lazy chunks of the route being opened, which the browser would load anyway
  a few round trips later; they are not initial JavaScript for every page.
- **The onboarding status is asked for at start.** `provideCore()` gets an
  environment initializer that calls `OnboardingStateService.load()` without
  waiting, so `GET /api/v1/onboarding` runs while the route's chunks load; the
  guard then awaits the same cached promise.
- **The editor loads while the file does.** In `editor-area.component.html` the
  `@defer` moves out of `@else if (file())`: for a Markdown entry it becomes
  `@defer (when file() !== undefined; prefetch on immediate)`, its content the
  `@if (file(); as file)` with `rs-editor-pane`, and its `@placeholder` and
  `@loading (minimum 0ms)` the existing spinner. A new `ChunkPreloader` in
  `web/core` adds `<link rel="modulepreload">` for the `editor` group as soon as
  a Markdown file is chosen, so CodeMirror's chunk and its imports arrive in one
  wave. The server hands the `editor` group's files to the web client in
  `index.html` as `<script type="application/json" id="fb-chunk-map" nonce="…">`
  (only the groups the client preloads itself: `editor`).
- **No measuring shortcut** _(plan's call)_: `perf-screen`'s editor measure
  still clicks before the editor's chunk is loaded, as plan 151 set it. The
  editor is not prefetched while the repository screen is idle: on slow 4G that
  would compete with the tree's own requests, and the measure would then time a
  warm chunk.

**Tech Stack:** Angular 22 (`@angular/build:application`, `@defer`), esbuild's
metafile, Express; Playwright (`perf-screen.mjs`); Vitest.

**Spec:** `docs/architecture/non-functional.md` NF-2.2, NF-2.7, NF-2.9, NF-14;
`docs/architecture/security.md` A-7.9; `docs/architecture/web-client.md` A-8.1,
A-8.17; `docs/wiki/release-checks.md`, "Plan 159: after compression".

## Global Constraints

- The shared constraints of [the step 6 index](2026-11-16-00-roadmap-step-6.md)
  apply.
- No new variable and no new dependency.
- Every tag the server adds to `index.html` carries the request's CSP nonce
  (NF-11.1); the Content Security Policy itself does not change.
- `index.html` stays `no-store` and is never precompressed (plan 159).
- A-7.9 (the preloads), and a new **A-8.18** in `web-client.md` (the chunk map,
  `ChunkPreloader`, the editor's `@defer`, and why idle prefetching was left
  out), are written in the same pull request.

## Review Focus

- **A CSP violation from an added tag** → a preload without the nonce is
  refused: the web-e2e test listens for `securitypolicyviolation` on a first
  load and on opening a file.
- **`en.json` fetched twice** (the preload's mode not matching the client's
  request) → the web-e2e test counts one request for `i18n/en.json`.
- **A chunk map from another build** (an image built with a stale `dist/`) → the
  server drops, with one `warn` line, every listed file missing from the web
  root at startup, so no preload points at a 404.
- **A path that looks like a route but is not** (`/repositories/abc`,
  `/REPOSITORIES/1`, `/repositories/1/files/a.txt`) → the right groups or none,
  never an error, tested in `serve-web-client.spec.ts`.
- **Switching files while the editor's chunk loads** → the `@defer` block shows
  the file chosen last, tested in the editor-area spec.

## Left out

- **Prefetching the editor while the repository screen is idle**: see the
  architecture; a separate decision if the measure is ever changed to a warm
  chunk.
- **HTTP/2 or 103 Early Hints**: the instance speaks HTTP/1.1 behind any HTTPS
  terminator (plan 159); NF-2's numbers are taken without one.
- **Inlining the onboarding status into `index.html`**: it would save the
  status's own round trip only when it is the last one left; measured in Task 5
  first.
- **Fonts and the icon sprite**: `fb:app-ready` does not wait for them.

## Outcome

- **NF-2.7 passes**: the first load, cold, from 8 waves to 5, 5.4 s to 3.7 s
  (desktop) and 5.6 s to 3.8 s (phone), on the developer machine and on the
  reference host alike (`docs/wiki/release-checks.md`, "Plan 162: round trips").
  Inlining the onboarding status stays left out: its request now runs beside two
  chunks that take as long.
- **NF-2.2 on slow 4G still misses**: the editor from 3 waves to 1, 3.4 s to 2.3
  s (desktop) and 3.6 s to 2.5 s (phone). What is left is the editor's 293 KB of
  Brotli at 180 KB/s, not round trips: plan 163 takes it.
- Where the work differs from the plan: the service is `ChunkPreloaderService`,
  the name the `toolkit-nx` generator gives, like the other services of
  `web/core`; the metafile's output paths are already relative to `browser/`,
  and `chunk-map.mjs` accepts both forms; the image deletes `browser-stats.json`
  once the map is written; the server also drops a listed name that is not a
  plain root-level `.js` file, and ignores a map of another `version`; the
  web-e2e target depends on `web:chunk-map`, so that its tests see the preloads.
  The measures were also taken on the reference host, with plan 161's image as
  the base.
