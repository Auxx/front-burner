# Changes Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 46 of [the step 3 index](2026-11-02-00-roadmap-step-3.md): the
left pane of the repository screen has **Files** and **Changes (3)**, and
**Changes** lists every changed file, up to date without a reload.

**Architecture:** A page-provided `GitStatusStore` holds the last `GitStatus`
and re-reads it on `git.changed` at once, on `files.changed` after
`STATUS_REFRESH_MS` (plan 45), and on every (re)connect. Later plans read the
store, so that the list, the bar and the commit form never disagree. **Changes**
is a second item of the existing activity bar, which already switches the side
pane (design pass): on narrow screens it opens the same drawer as **Files**.

**Tech Stack:** as before. `@angular/cdk/scrolling` is already used by `ui`'s
tree.

**Spec:** `docs/requirements/git-advanced.md` (GA-10 to GA-13, AC-GIT-002.2);
`docs/requirements/file-browser.md` FB-9, FB-41; `docs/architecture/api.md`
A-3.11; `docs/architecture/non-functional.md` NF-13.7.

## Global Constraints

- The shared constraints of [the step 3 index](2026-11-02-00-roadmap-step-3.md)
  apply.
- Each entry shows the file name, its folder in a quieter style, and its state
  in words and with a letter: **Modified** (M), **Added** (A), **Deleted** (D)
  (GA-11). Colour is never the only signal.
- The tab's label is "Changes (3)", and plain "Changes" while the status has not
  loaded or there are none (GA-10). The empty list says "No changes since the
  last commit." (GA-13).
- Which item is selected is remembered per device under `fb.<userId>.sideTool`
  _(plan's call)_, like the other pane memory (FB-8).
- The list renders with `cdk-virtual-scroll-viewport`, so that 20,000 changes
  stay usable _(plan's call)_.

## Review Focus

- **Status failing** (network or `409`) must keep the last list and say so
  quietly, not empty the list, which would look like "No changes" → Task 1 test
  `keeps the last status when a read fails`.
- **Two reads overlapping,** where the older answer arrives last, must not win →
  Task 1 test `ignores an answer older than the last one asked for`.
- **A burst of saves** must cause one read, not one per save → Task 1 test
  `reads once after a burst of files.changed`.
- **Moving to another repository in the same page** must not show the old
  repository's changes → Task 1 test `clears the status when the repository
  changes`.
- **A very long path on a 320 px screen** must truncate, not scroll sideways,
  with the full path available on focus → Task 2 test `shortens a long path,
  with the whole path available`.
