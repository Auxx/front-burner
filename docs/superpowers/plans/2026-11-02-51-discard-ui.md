> **For agentic workers:** REQUIRED SUB-SKILL: Use

**Goal:** Plan 51 of [the step 3 index](2026-11-02-00-roadmap-step-3.md): each
entry in **Changes** offers **Discard**, the list offers **Discard all**, both
ask first, and a late save can never bring a discarded change back.

**Architecture:** A `DiscardService` does the steps in order: confirm, drop
waiting saves and drafts (`OpenFilesService`), call the API, then reload or
close the open file. The order is what stops a late save, so it is one tested
method. The pending save is dropped before the request; if the request then
fails, the editor's content is still there and is saved again.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/git-advanced.md` (GA-23, GA-24, GA-43, criterion
8); `docs/requirements/editor.md` ED-20, ED-24;
`docs/requirements/file-browser.md` FB-39.

## Global Constraints

- The shared constraints of [the step 3 index](2026-11-02-00-roadmap-step-3.md)
  apply.
- The confirmation names how many files and says that the changes cannot be
  recovered (GA-23): "Discard changes to 1 file?" / "Discard changes to all 3
  files?", and "These changes can't be recovered." It uses a danger button, and
  **Cancel** has the focus.
- An open file that is discarded is reloaded at once, without ED-24's question.
  An added file that is discarded is closed (GA-24, FB-39).
- **Discard all** sends exactly the paths the list shows (plan 50).

## Review Focus

- **A save waiting when Discard is confirmed** must not come back → test
  `AC-GIT-002.8: discarding the open file while a save is waiting does not bring
  the change back`.
- **The discard failing** (network) must leave the editor's edits usable and say
  what failed → test `keeps the edits and offers Try again when the discard
  fails`.
- **The file's diff being shown when it is discarded** must end the diff → test
  `closes the diff of a discarded file`.
- **An edit typed while the confirmation is open:** the discard is what the user
  asked for, but the diff they saw is out of date; the dialog holds focus, so it
  can only come from another tab, where ED-24 applies → no extra test; say so in
  the pull request.
- **Discarding a modified file open in another tab** of the same user reaches it
  as a change on disk (ED-24), with its question → end-to-end test `another tab
  is asked about a file discarded here`.
