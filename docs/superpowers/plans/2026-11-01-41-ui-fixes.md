**Goal:** Plan 41 of [the design pass index](2026-10-30-00-design-pass.md):
seven fixes and change requests found after plans 34–40. Panels that open in
place slide, the code editor has no focus ring, the removal notice and the save
status stand apart from what is around them, and the dark canvas is a step
brighter.

**Architecture:** One SCSS mixin, `collapsible`, makes a region slide between
`0fr` and `1fr` grid rows. The dashboard guide and the removal notice use it.
The find panel repeats the same declarations in its CodeMirror theme. A closing
find panel leaves an inert copy that slides out. The other fixes change tokens:
a stale token name, a banner background property, the dark canvas, and a new
`accent-indicator` token.

**Tech Stack:** Angular 22, SCSS, CodeMirror 6 (`@codemirror/view` panels and
themes), Vitest, Playwright, `ai-tools` (`tokens`, `colour`, `story`).

**Spec:** The decisions below were agreed in review on 2026-11-01. There is no
separate design file. The items are:

| # | Item                                                         | Kind   |
| - | ------------------------------------------------------------ | ------ |
| 1 | Dashboard **How it works** slides open and closed            | Change |
| 2 | The code editor has no focus ring, as in IDEs                | Bug    |
| 3 | Find panel slides out; its replace row slides; chevron turns | Bug    |
| 4 | Removal notice **Details** slides open and closed            | Change |
| 5 | Removal notice on its own shade, as a full-width strip       | Bug    |
| 6 | Save status in muted, smaller text (a stale token name)      | Bug    |
| 7 | Dark canvas `neutral-27` → `neutral-30` (option B)           | Change |

Requirements touched: DS-13 and AC-DASH-001.3 (dashboard), ED-11 (editor), SH-17
and SH-18 (preview HTML), NF-13.3, A-10.12, A-10.19, A-10.30.

## Global Constraints

- The shared constraints of [the index](2026-10-30-00-design-pass.md) apply:
  tokens only, light mode and 320 px keep working, the contrast spec passes,
  accessibility kept, docs in the same pull request, a visual check of record.
- Motion: open with `--ui-duration-base` and `--ui-easing-standard`, close with
  `--ui-duration-base` and `--ui-easing-exit`. With `prefers-reduced-motion` the
  tokens are `0s`, and nothing may wait for a transition or animation that does
  not run (A-10.12).
- A collapsed region is `inert` and `visibility: hidden`, so it cannot be tabbed
  into and screen readers skip it. The element stays in the document so that
  `aria-controls` always names an element. Bind it as `[attr.inert]` (jsdom has
  no `inert` property).
- SCSS modules are used with a namespace (`@use 'x'`), never `as *`.
- No new runtime dependency. `@angular/animations` is not added.

## Review Focus

- **Clicking fast**: toggling **How it works**, **Details** or the find chevron
  twice in a row, mid-transition, ends in the state that matches `aria-expanded`
  (Task 1 and Task 2 tests toggle twice and check both).
- **Reduced motion**: with zero durations, a closed find panel leaves no copy
  behind and every region opens and closes at once (Task 2 test with
  `animationDuration` `0s`; Task 1 and 2 screenshots with `--reduced-motion`).
- **Switching files with the find panel open** shows no slide-out over the new
  file (Task 2 test: no `.fb-find-closing` after `show()` with another state).
- **Focus in a collapsing region**: collapsing the replace row while its field
  has focus moves focus to the find field, as today (Task 2 test, existing case
  kept).
- **Controls on the brighter canvas**: anything at `neutral-30` that sits
  directly on the canvas, such as header buttons or the activity bar's selected
  item, keeps a visible edge (Task 5 screenshots; stop and ask if one
  disappears).
