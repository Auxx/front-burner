# Push API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 57 of [the step 3 index](2026-11-02-00-roadmap-step-3.md): `POST
…/git/push` starts a push job, a client can read how it ended, and the push
finishes even if the user logs out.

**Architecture:** The request does the checks that need the user's session,
above all whether the key is unlocked, then queues a job and answers `202`. A
protected key is copied for the job, in the map that clones already use, moved
to the credentials library so that it can serve every job type (RC-19). A push
that git refused is a job that **finished**: the handler returns `{ kind:
'failed', code, params }` as its result, because `jobs.error_code` has no room
for parameters and a refused push is not a failure of the runner _(plan's
call)_. The client reads the result after `job.finished`, as events are not
state (A-3.11).

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/git-advanced.md` (GA-2, GA-3, GA-4, GA-8's backend
half, GA-29 to GA-32; criterion 19, the API for 10 and 12);
`docs/requirements/repo-credentials.md` (RC-1 to RC-5, RC-19, criterion 11);
`docs/requirements/commit-author.md` CA-15; `docs/architecture/jobs.md`,
`docs/architecture/overview.md` A-1.13.

## Global Constraints

- The shared constraints of [the step 3 index](2026-11-02-00-roadmap-step-3.md)
  apply.
- The job type is `sync.push`, pool `fetch` (A-6.5), `onInterrupted: 'fail'`,
  with the repository ID set, and the dedupe key `push:<repositoryId>`, so that
  a second click gets the same job. Its payload is `{ branch }`; never a secret
  (A-6.3).
- The request refuses, in this order, with `409`: `merge-in-progress`,
  `no-branch` (detached), `no-commits`, `nothing-to-push` (an upstream, and
  `ahead` is 0), then `key-locked` from `resolveForGit` with `touch: true`.
- An HTTPS repository with no credentials that gets `auth-failed` reports the
  code `no-credentials` (RC-4).
- The handler runs inside `NetworkLock.run`, not the working-tree lock (A-5.3),
  and publishes `git.changed` when it ends, either way.

## Review Focus

- **A running push when the user logs out** must finish → Task 3 test
  `AC-REPO-002.11`, using the HTTP server's `delayMs`.
- **The token replaced between queueing and running** must use the new one,
  since the job reads saved credentials when it runs and only a protected key is
  held → Task 1 test `reads saved credentials when the job runs`.
- **A restart during a push** must end the job as failed with `interrupted`, and
  the result endpoint must say so → Task 2 test `reports an interrupted push`.
- **Another user's job ID, or a job of another repository,** answers `404` →
  Task 2 test `answers another user's job like a missing one`.
- **A key copy that is never released** would keep a secret in memory: every end
  of a job drops it → Task 1 test `drops the key copy on done, failed and
  cancelled`.
