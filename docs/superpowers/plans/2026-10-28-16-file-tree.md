# File Tree Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 16 of [the step 2 index](2026-10-28-00-roadmap-step-2.md): the
repository screen shows the working copy as a file tree. Folders load when
expanded; ignored entries are marked; selecting an entry updates the route and
shows, in the editor area, either the Markdown file's name (until the editor
exists) or why the entry cannot be opened. The screen opens the right file
first, and each device remembers expanded folders and the last file.

**Architecture:** A `FileTreeStore` service, provided by the repository screen
page, holds the loaded listings by folder path and turns them into `ui-tree`
nodes (A-8.2). Loading, errors and "n more items" are extra, non-entry rows,
whose values start with NUL so that they can never be a path. A `FileTree`
component renders `ui-tree` with a row template. Selection is the route: the
tree's `selected` is the route's `path`, and selecting a node navigates.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/file-browser.md` (REQ-FILE-001: FB-9 (closing),
FB-12 to FB-23, FB-33's tree half, FB-43, FB-44, FB-46; criteria 4 (drawer), 5,
6, 7 (web half), 12, 22, and the browsing half of 23); `navigation.md` NV-13;
`docs/architecture/web-client.md` A-8.2.

## Global Constraints

- The shared constraints of [the step 2 index](2026-10-28-00-roadmap-step-2.md)
  apply.
- Per-device memory keys: `fb.<userId>.repo.<repositoryId>.expanded` (a JSON
  array of folder paths) and `fb.<userId>.repo.<repositoryId>.lastFile`.
- English texts, exactly:
  - FB-21's five messages; for the two found only on opening (too large, not
    UTF-8), nothing yet — they come with plan 23;
  - a Markdown file, until plan 25: its name as the heading and "The editor
    comes in a later version.";
  - a path that does not exist (FB-13): "This file doesn't exist." _(plan's
    call)_;
  - the ignored icon: "Ignored by .gitignore. Git won't commit this file." /
    "Ignored by .gitignore. Git won't commit anything in this folder." (FB-20a);
  - an expanded empty folder: "Empty folders aren't saved in git. Add a file to
    keep this folder." (FB-33);
  - "{count, plural, one {# more item} other {# more items}} not shown" (FB-18);
  - "This folder could not be loaded" and **Try again** (FB-44).
- Accessible names: `<name>, <kind>[, Markdown][, ignored][, empty]` with kinds
  "folder", "file", "symbolic link", "submodule" (FB-46). They start with the
  visible name (WCAG 2.5.3).
- Page title with a file: `<file name> · <repository name> · Front Burner`
  (NV-13).
- A test that covers part of a criterion still starts with its ID; the
  requirement's **State** cannot reach Done before every point is built, so the
  status stays honest. Criterion 10 is all open-time checks, so its tests come
  with plan 23.

## Review Focus

- **A remembered last file that has since been deleted** must fall back to the
  README, not show "This file doesn't exist." → Task 3 test `falls back to the
  README when the last file is gone`.
- **A route to a file under a folder that does not exist** (`nope/x.md`) must
  show "This file doesn't exist." and leave the tree usable, not spin forever →
  Task 3 test `shows a missing path's message`.
- **Remembered expanded folders that no longer exist** must be dropped silently,
  without an error row → Task 1 test `drops remembered folders that are gone`.
- **Tapping the ignored icon on a touch screen** must show the message and must
  not open the file → Task 2 test `shows the ignored message without selecting
  the row`.
- **A folder that fails to load, then loads on Try again** must keep the rest of
  the tree as it was (expanded folders, the selection) → Task 1 test `retries
  one folder without touching the others`.

### Task 1: The tree store

**Files:**

- Create (generated service):
  `libs/web/feature-repository-screen/src/repository-screen/services/file-tree-store`
  (+ `.spec.ts`)
- Create: `src/repository-screen/models/tree-entry.model.ts`

**Interfaces:**

- Consumes: `FilesApi.listFolder(id, { path })` (plan 14); `CurrentUserService`.
- Produces:
  - `interface TreeEntry extends TreeNode { kind: EntryKind | 'loading' |
    'error' | 'more' | 'empty-note'; entry?: Entry; path: string }` — extra rows
    have `value: '\u0000<kind>:<folder path>'`, `selectable: false`, except
    `error`, which is selectable and means **Try again**.
  - `FileTreeStore` (provided by the page):
    - `init(repositoryId: number): void` — loads the root and the remembered
      expanded folders that still exist (parents before children);
    - `nodes: Signal<readonly TreeEntry[]>`; `expanded: WritableSignal<readonly
      string[]>` (written back to `localStorage` on change);
    - `load(folder: string): void` — fetch and replace that folder's children; a
      loading row while in flight, an error row on failure (FB-43, FB-44);
    - `entry(path: string): Entry | undefined` — from the loaded listings;
    - `resolve(path: string): Promise<Entry | null>` — loads the ancestors of
      `path` as needed and expands them (FB-14); `null` when any part is
      missing.

      shown"); `adds the empty-folder note to an expanded empty folder`;
      `composes accessible names from kind and flags`; `resolves a nested path
      by loading and expanding its ancestors`.
- [ ] **Step 2: Run them and see them fail** — `npx nx test

### Task 2: The tree component

**Files:**

- Create (generated component): `components/file-tree` (+ `.spec.ts`)
- Modify: `libs/ui/src/content/models/icon-name.model.ts` and
  `libs/ui/src/assets/icons.svg` (only the icons that are missing: `folder`,
  `file`, `file-symlink-file`, `file-submodule`, rebuilt with `node
  tools/ai-tools/src/bin/icons.mjs sprite --write`);
  `apps/web/public/i18n/en.json`

**Interfaces:**

- Consumes: `FileTreeStore` (Task 1); `ui-tree`, `uiTreeNode`, `ui-icon`,
  `uiTooltip`, `ui-popover`.
- Produces: `FileTreeComponent` (`rs-file-tree`), input `selected: string |
  null`, output `select: string` (a path) and `retry: string` (a folder). Each
  row: the kind's icon (`markdown` for Markdown files, FB-20), the name, and for
  an ignored entry the ignored colour and the `diff-ignored` icon with its
  message (FB-20a). The icon shows the message as a tooltip on hover and when
  its row is the keyboard's active row, and as a popover on tap; a tap stops
  propagation, so it neither selects nor toggles. Its touch target is at least
  24 × 24 px (NF-13.5). The ignored colour is a design token checked with the
  `ai-tools` contrast tool in both schemes.

### Task 3: Selecting entries and the first file

**Files:**

- Create (generated components): `components/entry-message` (+ `.spec.ts`)
- Create (generated service): `services/first-file` (+ `.spec.ts`)
- Modify: `pages/repository-screen/*`, `components/editor-area/*`,
  `apps/web/public/i18n/en.json`

**Interfaces:**

- Consumes: `FileTreeStore.resolve`, `.entry` (Task 1); `FileTreeComponent`
  (Task 2).
- Produces:
  - `FirstFile.pick(repositoryId: number): Promise<string | null>` — FB-12's
    order: the remembered last file if `resolve` finds it and it is a Markdown
    file; else the first root entry that is a Markdown file named `README` with
    any Markdown extension, ignoring case; else `null`.
  - The page: with an empty route path it navigates (with `replaceUrl`) to
    `FirstFile.pick`'s file, or shows the empty state; with a path, it
    `resolve`s it, selects and highlights it (FB-14) and remembers it as the
    last file if it is a Markdown file. Selecting a node navigates to
    `/repositories/<id>/files/<path>` and closes the drawer (FB-9). The title
    follows NV-13.
  - `EntryMessageComponent` (input `entry: Entry | null`, `path: string`): the
    FB-21 message for its kind, or FB-13's for `null`.
  - `EditorAreaComponent` shows the empty state, the entry message, or a
    Markdown file's name with the "later version" note.
