# Commit Author, Changes, Commit and Push — Plan Index

> Status: **Accepted**

Plans 13 to 41 finished MVP step 2, except the leftovers named in
[its index](2026-10-28-00-roadmap-step-2.md). This index splits MVP step 3
(`docs/product/mvp.md`, "Order of work": commit author, status, diff, discard,
commit and push, with push credentials and key unlock) into small plans,
numbered on from 42. Each plan is one branch and one pull request, leaves CI
green, and can be shown to someone when it is merged. At the end of step 3 the
operator sees their changes and diffs, discards a change, commits selected files
as the right author, and pushes, fixing credential problems without leaving the
repository screen. This is exit criterion 7 of the MVP, and exit criterion 10
for push.

There is no separate design spec: the requirements and the architecture
documents are the spec. Each plan names the requirement IDs it implements and
records its own decisions as _(plan's call)_; a decision that changes or adds to
an architecture document updates that document in the same pull request.

## Shared constraints

The shared constraints of [the step 1 index](2026-10-26-00-roadmap.md) and
[the step 2 index](2026-10-28-00-roadmap-step-2.md) apply to every task of every
plan here, with these additions:

- **Library homes are the ones `docs/architecture/modules.md` already names:**
  `server/feature/preferences`, `server/feature/sync`, `web/feature-preferences`
  and `web/repository-dialogs`. Git UI goes into `feature-repository-screen`
  (A-2.2a).
- **Every git endpoint is under `/repositories/:id/git`, with the OpenAPI tag
  `git`,** and finds its working copy with `OpenableRepository.root(userId, id)`
  (plan 14), so that another user's repository is answered like a missing one
  (GA-1).
- **Every change to the working tree or index goes through
  `WorkingTreeGuard.change`,** which refuses it with `409 merge-in-progress`
  (GA-4). Network steps stay outside the lock (A-5.3).
- **Features never build git command lines** (A-5.10). Every engine call that
  takes a client's paths first checks each with `resolveInWorkingCopy(root,
  path, { symlinkLeaf: true })`, then passes them with `git --literal-pathspecs`
  and, for a list, `--pathspec-from-file=- --pathspec-file-nul`, so that a name
  can't be read as pathspec magic and a long list can't overflow the command
  line.
- **Read-only git commands run with `--no-optional-locks` and outside the
  working-tree lock,** like `GitEngine.uncommittedUnder`, so that a save never
  waits behind them (NF-2.3). _(Plan 44's call; it updates A-5.3.)_
- **The commit author is set only through `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`,
  `GIT_COMMITTER_NAME` and `GIT_COMMITTER_EMAIL`** in the run's environment,
  which beat every git configuration (CA-2).
- **After a change to git state,** the backend publishes `git.changed` (plan
  44), and `files.changed` when working tree files changed. Clients read the new
  state over REST (A-3.11).
- **UI text uses git's words** (GA-5). Colour is never the only signal
  (NF-13.7), and everything works by touch alone and with the keyboard alone
  (GA-6).
- Tests that cover an MVP criterion start their title with its ID, and every
  plan updates the "Implementation status" table of `docs/product/mvp.md` as its
  "Keeping it up to date" note says. `doc-ids.mjs criteria` counts a criterion
  as tested as soon as one title names it, so a test that covers only the part
  of a criterion built so far does **not** start with its ID; the plan or step
  that finishes the criterion names it.

## Left out of these plans

Each is deferred to the plan or step that builds it, not dropped:

- **Step 4:** **Fetch** and **Pull** in the bar, and the branch list. Until then
  the branch in the bar is plain text, not a button (GA-7, GA-36), and the **to
  pull** count only moves with what a push learns. "The remote has new commits.
  Pull first." has no **Pull** button (GA-30). A credential problem on a
  background fetch (RC-6, AC-REPO-002.13), fetching without credentials
  (AC-REPO-002.2), fetches stopping and resuming for a locked key (the fetch
  half of RC-15 and AC-REPO-002.8), the question before a merge commit (CA-14,
  AC-GIT-001.9), and the conflict list in place of **Changes** (GA-4's screen).
- **Step 5:** the repository management page's commit author section (the second
  bullet of CA-9, and **Use my default** on the page; plan 42 builds its API)
  and its way into the credentials dialog (the second half of RC-11).
  `sync_state` and the repository warnings of RM-8, which also read a push's
  credential problem.
- **Still after this step:** the version line of the user menu and the banners
  of NV-15, and remembering the **Wrap** choice (ED-10), which `mvp.md` keeps
  limited in the MVP although the Preferences page now exists.
