# Git Engine over SSH Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 8 of [the index](2026-10-26-00-roadmap.md): the backend can
parse, check and generate SSH keys, and check access to and clone SSH remotes
with an unlocked key that never leaves its memory, trusting only built-in,
operator and user-accepted host keys, and telling an unknown host key (with its
fingerprint) from a changed one.

**Architecture:** In `server/core/git`: an `ssh/` folder for keys (parsing,
checks, generation, fingerprints) on top of `ssh2`'s key utilities, our own
small ssh-agent protocol server (A-5.4: `ssh2`'s agent breaks on OpenSSH's
`session-bind` extension), the known hosts list (A-5.6), and a host key probe
that fetches an unknown host's key through the address rules. The plan 7 broker
gains its SSH half: the agent socket, a per-command `ssh_config` used with `ssh
-F`, and the `ProxyCommand` helper through the egress proxy (A-5.7).

**Tech Stack:** as before, plus `ssh2` 1.17.0 and `@types/ssh2` 1.15.6 (dev);
OpenSSH 8.9 or later on the host.

**Spec:** `docs/architecture/git-engine.md` A-5.4 (SSH), A-5.5 (the
`UnlockedKey` part), A-5.6, A-5.7 (SSH); `docs/requirements/repo-add.md` AR-17,
AR-24, AR-26 to AR-29 (key handling), AR-32, AR-42 (SSH failures);
`docs/architecture/overview.md` A-1.15 (`FRONT_BURNER_KNOWN_HOSTS_FILE`). Spike:
`spike/ssh-credential-broker` (`lib/broker.js`, `lib/known-hosts.js`,
`lib/key-store.js`) and its findings in `docs/architecture/spikes.md`.

## Global Constraints

- The shared constraints of [the index](2026-10-26-00-roadmap.md) apply.
- Extends plan 7's `GitCredentials`, `openBroker`, `GitEngine`,
  `classifyGitFailure` (`host-key-unknown` and `host-key-changed` start being
  produced) and `proxy-connect.cjs`; uses plan 3's `resolveAllowed`. A wrong
  passphrase is an `SshKeyError`, found when the key is unlocked, never a git
  failure.
- `ssh2` is used only to parse keys, sign, generate Ed25519 keys and, in the
  probe and tests, as an SSH client or server. The agent protocol is ours.
- A decrypted private key exists only inside an `UnlockedKey` object in the
  backend's memory: never in a file, an environment variable, a log or an error
  message (AR-17, AR-31). Public keys and known hosts may be written to the
  broker directory.
- Accepted key types (AR-27): Ed25519, ECDSA (P-256, P-384, P-521), RSA of at
  least 2048 bits. DSA and anything else is refused.
- The per-command `ssh_config` contains only paths we created and fixed values;
  the remote's host and port reach the `ProxyCommand` helper through its
  environment (A-5.7).

## Review Focus

- **The agent asked to sign something that is not an SSH login** for the
  expected user and key (a forged request on the socket) must answer failure →
  Task 2 test `refuses to sign anything but a login request`.
- **OpenSSH's `session-bind@openssh.com` message** (sent before every login
  since 8.9) must get a failure reply without breaking the stream → Task 2 test
  `answers extensions with failure and keeps going`, and Task 4's clones with
  the host's real `ssh`.
- **A host whose key changed** must fail as `host-key-changed`, never as
  `host-key-unknown` (which would offer **Trust**, AR-32) → Task 4 test `tells a
  changed host key from an unknown one`.
- **A pasted key that is encrypted, with no passphrase, a wrong one, or a
  passphrase for a key that is not encrypted** must each be refused on the right
  field (AR-27, criterion 11) → Task 1 tests.
- **A remote on a non-standard port** (`ssh://git@host:2222/x`) must check and
  store the host key as `[host]:2222`, so that trusting port 2222 does not trust
  port 22 → Task 3 test `writes non-standard ports in brackets`.

**Interfaces:**

- Produces:
  - `SSH_KEY_PROBLEMS = ['invalid-key', 'unsupported-type', 'rsa-too-short',
    'passphrase-required', 'wrong-passphrase', 'passphrase-not-needed']`; `class
    SshKeyError extends Error { problem: SshKeyProblem; field: 'privateKey' |
    'passphrase' }` (`passphrase-*` and `wrong-passphrase` on `passphrase`, the
    rest on `privateKey`, AR-27).
  - `SshKeyInfo = { type: 'ed25519' | 'ecdsa' | 'rsa'; bits: number; publicKey:
    string (authorized_keys line, no comment); fingerprint: string ('SHA256:' +
    unpadded base64); encrypted: boolean }`.
  - `inspectPrivateKey(text: string, passphrase?: string): SshKeyInfo` — at most
    16 KiB (AR-26); OpenSSH or PEM; throws `SshKeyError`.
  - `unlockPrivateKey(text: string, passphrase?: string): UnlockedKey` — the
    same checks, then the decrypted key.
  - `class UnlockedKey` — wraps `ssh2`'s parsed key: `publicBlob: Buffer`,
    `algorithm: string`, `sign(data: Buffer, hash?: 'sha256' | 'sha512'):
    Buffer`; no method returns the private key; `toJSON()` and
    `[util.inspect.custom]` return `'[UnlockedKey]'`.
  - `generateEd25519Key(comment: string): { privateKey: string; publicKey:
    string }` — OpenSSH format, no passphrase (AR-29); `publicKey` ends with the
    comment.
  - `fingerprintOf(publicKeyLine: string): string`.

      (`unsupported-type`); `refuses RSA under 2048 bits` (`rsa-too-short`);
      `refuses text that is not a key` (`invalid-key`); `refuses an encrypted

      `refuses a wrong passphrase`; `refuses a passphrase for a key that is not

### Task 2: The ssh-agent protocol server

**Files:**

- Create: `libs/server/core/git/src/ssh/ssh-agent.ts` (+ `.spec.ts`)

**Interfaces:**

- Consumes: `UnlockedKey` (Task 1).
- Produces: `openSshAgent(options: { socketPath: string; key: UnlockedKey; user:
  string; maxSignatures?: number (default 4) }): Promise<SshAgent>`, `SshAgent =
  { signatures: number; refusals: string[]; close(): Promise<void> }`. The
  protocol, framed by the 4-byte length (frames of 0 or over 256 KiB close the
  connection):
  - `SSH_AGENTC_REQUEST_IDENTITIES` (11) → `SSH_AGENT_IDENTITIES_ANSWER` (12)
    with the one key and an empty comment;
  - `SSH_AGENTC_SIGN_REQUEST` (13) → `SSH_AGENT_SIGN_RESPONSE` (14) only when
    the key blob is ours and the data is an `SSH_MSG_USERAUTH_REQUEST` (50) for
    `user`, service `ssh-connection`, method `publickey` or
    `publickey-hostbound-v00@openssh.com`, with the signature flag set and our
    key blob, and fewer than `maxSignatures` were made; the flags
    `SSH_AGENT_RSA_SHA2_256` (2) and `_512` (4) choose the hash for RSA;
  - everything else, including `SSH_AGENTC_EXTENSION` (27), →
    `SSH_AGENT_FAILURE` (5).

- [ ] **Step 1: Write the failing tests**: `lists the one identity` (`ssh-add
      -L` with `SSH_AUTH_SOCK` prints the public key); `signs a login request`
      (an `ssh2` `Client` with `agent: socketPath` logs in to an `ssh2` test
      server that checks the signature); `signs RSA with SHA-256`; `refuses to
      sign anything but a login request` (a raw request with other data → `5`);
      `refuses another user`; `stops after the maximum`; `answers extensions
      with failure and keeps going` (send a type-27 frame, then a
      request-identities frame on the same connection: `5`, then `12`).
- [ ] **Step 2: Run them and see them fail** — `npx nx test server-core-git`.
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run them and see them pass** — `npx nx test server-core-git`.
- [ ] **Step 5: Commit** — `feat(git): add the ssh-agent for one operation`

### Task 3: Known hosts and the host key probe

**Files:**

- Create: `libs/server/core/git/src/ssh/known-hosts.ts` (+ `.spec.ts`)
- Create: `libs/server/core/git/src/ssh/host-key-probe.ts` (+ `.spec.ts`)
- Modify: `libs/server/core/config/src/config/*` (+ spec):
  `FRONT_BURNER_KNOWN_HOSTS_FILE`
- Modify: `docs/architecture/data.md` A-4.4 (`known_hosts` keeps the full public
  host key next to its fingerprint: `ssh` needs the key) and `git-engine.md`
  A-5.6 (the probe)

**Interfaces:**

- Produces:
  - `HostKey = { host: string; port: number; type: string; key: string (base64
    blob); fingerprint: string }`.
  - `BUILT_IN_KNOWN_HOSTS: readonly string[]` — the six lines of
    `spike/ssh-broker/lib/known-hosts.js`, with the date they were checked.
  - `Config.knownHostsFile: string | undefined`; `loadInstanceKnownHosts
    (config): string[]` — the operator's file replaces the built-ins (AR-32):
    comment and blank lines dropped, hashed (`|1|`) entries refused with a
    startup error naming the line number.
  - `knownHostsLine(entry: { host; port; type; key }): string` — `host type
    key`, or `[host]:port type key` when `port !== 22`.
  - `probeHostKey(remote: { host: string; port: number }, egress: EgressOptions,
    lookup?): Promise<HostKey>` — resolves with `resolveAllowed`, connects to a
    checked address with `net.connect`, runs an `ssh2` `Client` handshake over
    that socket with a `hostVerifier` that records the key and refuses, so no
    login happens; host key algorithms in OpenSSH's default order (`ssh-ed25519`
    first). Timeout 15 s; a refused or unreachable host throws
    `GitOperationError('host-unreachable')`.

- [ ] **Step 1: Write the failing tests**: `writes non-standard ports in
      brackets`; `replaces the built-ins with the operator's file`; `refuses
      hashed entries`; `probes a host key` (an `ssh2` test server with a known
      Ed25519 host key: type and fingerprint match); `refuses to probe a blocked
      address`.
- [ ] **Step 2: Run them and see them fail** — `npx nx run-many -t test -p

### Task 4: Access check and clone over SSH

**Files:**

- Modify: `libs/server/core/git/src/broker/broker.ts` (+ `.spec.ts`),
  `src/engine/git-engine.ts` (+ `.spec.ts`), `src/engine/git-errors.ts` (+
  `.spec.ts`)
- Create: `libs/server/core/git/src/testing/git-ssh-server.ts` (exported from
  the `testing` entry point)

**Interfaces:**

- Consumes: Tasks 1 to 3; plan 7's broker, engine and helpers.
- Produces:
  - `GitCredentials` gains `{ kind: 'ssh'; key: UnlockedKey }`; `accessCheck`
    takes a third, optional argument `knownHosts: string[]`, and `clone`'s
    request an optional `knownHosts: string[]` (the user's accepted hosts as
    lines; the instance list is always added).
  - Broker, for SSH: the agent on `<dir>/s` for the URL's user, or `git` when
    the URL has none; `<dir>/id.pub`, `<dir>/known_hosts` and `<dir>/ssh_config`
    (mode `0600`) with exactly the settings of the spike's config (A-5.4), plus
    `User git` when the URL has no user and `ProxyCommand <process.execPath>
    <helpersDir>/proxy-connect.cjs`; env `GIT_SSH_COMMAND=ssh
    -F <dir>/ssh_config`, `GIT_SSH_VARIANT=ssh`, `FB_EGRESS_SOCK`,
    `FB_BROKER_TOKEN`, and `FB_EGRESS_TARGET=<host>:<port>` from the parsed
    remote.
  - `classifyGitFailure`, checked first for SSH (A-5.6): `REMOTE HOST
    IDENTIFICATION HAS CHANGED` or `Host key for .* has changed` →
    `host-key-changed`; `No .* host key is known` or `Host key verification
    failed` → `host-key-unknown`; `Permission denied (publickey` →
    `auth-failed`; `egress proxy refused` from the helper → `host-unreachable`.
  - On `host-key-unknown` the engine runs `probeHostKey` and throws
    `GitOperationError('host-key-unknown')` with `params: { host, port, type,
    fingerprint, key }` (AR-32: the web client shows type and fingerprint; the
    key is what plan 10 stores on **Trust**).
  - `startGitSshServer(options: { repositories: Record<string, string>;
    authorizedKeys: string[]; hostKey?: string }): Promise<{ host: string; port:
    number; hostKeyLine: string; close() }>` — an `ssh2` server that accepts
    only the authorized keys (verifying the signature) and serves
    `git-upload-pack '<path>'` by spawning it.
