# Sessions and Password Login API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 1 of [the index](2026-10-26-00-roadmap.md): the backend logs a
password user in, issues an auth token and a refresh token, refreshes and
rotates them, logs out, records every attempt in the login audit log, and
refuses every non-public route without a valid auth token.

**Architecture:** Tokens and sessions live in `server/feature/auth` next to
onboarding. An Express middleware identifies the caller from the `Authorization`
header before any guard runs, so that the rate limiter can key authenticated
requests by user (NF-11.4); a global `AuthGuard` then refuses every route not
marked `@Public()`. Active sessions are cached in memory (A-7.2, one process).
The refresh token is `<session id>.<secret>`, so a rotated token still finds its
session and its reuse revokes it (LG-36).

**Tech Stack:** as in the onboarding plan, plus `jose` 6.2.13 (HS256 JWTs) and
`cookie-parser` 1.4.7 with `@types/cookie-parser` 1.4.10. New library
`shared/util` (`@nx/js:library`).

**Spec:** `docs/requirements/auth-login.md` (REQ-AUTH-003: LG-1, LG-5, LG-8,
LG-10 to LG-16, LG-24, LG-27 to LG-37, LG-39 backend half, LG-41 to LG-44,
LG-46, LG-47, LG-61 to LG-67); `docs/requirements/auth-onboarding.md` criterion
4 ("that user can log in"). Architecture: `security.md` A-7.2, A-7.11; `api.md`
A-3.5, A-3.8; `overview.md` A-1.12, A-1.15; `data.md` A-4.4; `non-functional.md`
NF-11.4.

## Global Constraints

- The shared constraints of [the index](2026-10-26-00-roadmap.md) apply.
- `FRONT_BURNER_JWT_SECRET` becomes **required**: update `.env.example`
  (development value of 48 characters with a comment), `apps/server-e2e`'s
  `server-process.ts`, `apps/web-e2e`'s `instance.ts` and every server spec that
  builds an environment, in the task that adds it.
- Fixed texts: login failure "Wrong username or password" (LG-14); the English
  fallback of `auth-token-expired` is "The auth token has expired.", of
  `unauthenticated` "Log in to continue.", of `refresh-refused` "Your session
  has expired. Please log in again".
- `jose` and `openid-client` are ESM-only; the server bundle is CommonJS and
  relies on Node 24 loading ESM through `require`. The `server-e2e` login test
  is the proof that this works from `dist/`; do not add a dynamic `import()`
  workaround unless that test fails.
- Login, refresh and logout work only with HTTPS cookies (LG-32); browsers
  accept `Secure` cookies on `http://localhost`, which the e2e tests use.

## Review Focus

- **A JWT signed with another algorithm** (`alg: none`, HS512, or RS256 with the
  secret as a public key) must be refused, not verified → Task 5 test `refuses
  an auth token with another algorithm`.
- **A changed `FRONT_BURNER_JWT_SECRET`** must refuse every old auth token with
  `auth-token-expired`, so that clients refresh and users stay logged in
  (LG-64), not `unauthenticated`, which would log everyone out → Task 5 test
  `reports a token signed with another secret as expired`.
- **A password with leading or trailing spaces, or typed in NFD** (macOS
  keyboards) must log in exactly when it was set that way, never trimmed or
  compared byte for byte (LG-12, PP-1, PP-2) → Task 6 tests `does not trim the
  password` and `matches an NFD password against an NFC hash`.
- **A refresh token used after the session's absolute expiry** (LG-29: 30 days
  from login, refreshing does not extend it) must be refused even though it was
  never rotated → Task 5 test `refuses a refresh after the session expired`.
- **An email typed with a trailing space or another letter case** must log the
  same user in, and the audit entry must keep the email as entered → Task 6 test
  `finds the user ignoring case and spaces`.

### Task 5: Auth tokens and sessions

**Files:**

- Create: `libs/server/feature/auth/src/sessions/auth-token.service.ts` (+
  `.spec.ts`)
- Create: `libs/server/feature/auth/src/sessions/session.service.ts` (+
  `.spec.ts`)
- Create: `libs/server/feature/auth/src/sessions/session-cache.ts`

**Interfaces:**

- Consumes: `Config` (Task 2), `sessions`, `users` (Task 4).
- Produces:
  - `AuthTokenService.sign(claims: { userId: number; sessionId: string; tokenId:
    string }, expiresAt: Date): Promise<string>` — HS256 with `jose`'s
    `SignJWT`; claims `sub` (user ID as a string), `sid`, `jti`, `iat`, `exp`
    and nothing else (LG-28).
  - `AuthTokenService.verify(token: string): Promise<AuthTokenResult>` where
    `type AuthTokenResult = { ok: true; userId: number; sessionId: string } | {
    ok: false; reason: 'expired' | 'invalid' }`. `jwtVerify` with `algorithms:
    ['HS256']`. A bad signature counts as `expired` when the token is
    well-formed HS256 with an `exp` in the future (LG-64: tokens of a changed
    secret make clients refresh); everything else malformed is `invalid`.
  - `SessionCache` (plain class): `get(id): CachedSession | undefined`, `set(id,
    value)`, `delete(id)`; `CachedSession = { userId: number; expiresAt: number;
    revoked: boolean }`.
  - `SessionService` (injectable):
    - `start(user: { id: number }, loginMethod: 'password' | 'oidc', delivery:
      RefreshTokenDelivery): Promise<IssuedSession>`;
    - `refresh(refreshToken: string): Promise<IssuedSession>` — throws
      `ApiErrorException(401, 'refresh-refused')` when the token is malformed,
      the session is unknown, expired or revoked, or the user is disabled
      (LG-35, LG-24); on a hash mismatch it revokes the session, records
      `refresh-token-reused` through an injected `onReuse(session)` callback
      provided by Task 6's `LoginAuditService`, and throws the same error
      (LG-36);
    - `revokeByRefreshToken(refreshToken: string): void` — logout; unknown or
      malformed tokens are ignored (LG-39);
    - `revokeAllOf(userId: number): void` (LG-25, LG-57);
    - `isActive(sessionId: string, userId: number): boolean` — cache first,
      database on a miss (A-7.2).
  - `IssuedSession = { sessionId: string; delivery: RefreshTokenDelivery;
    tokens: SessionTokens; refreshToken: string }` (`tokens.refreshToken` is set
    only for `body` delivery).
  - Values: session ID `randomBytes(16)` in base64url; refresh token
    `${sessionId}.${randomBytes(32) base64url}` (LG-29: 256 bits); stored hash
    SHA-256 hex of the whole token, compared with `constantTimeEquals`; auth
    token `exp` is `min(now + authTokenTtlMs, session expiresAt)`; session
    `expiresAt` is `createdAt + refreshTokenTtlMs` and never moves (LG-29);
    `lastUsedAt` is set on start and refresh.
