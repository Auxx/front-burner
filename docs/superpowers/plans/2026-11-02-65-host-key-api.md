# Changed Host Key API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 65 of [the step 3 index](2026-11-02-00-roadmap-step-3.md): a
`host-key-changed` error carries the fingerprint that was trusted and the new
one, and a new endpoint replaces the user's trusted key for that host and port,
with a line in the log.

**Architecture:** `runNetwork` already probes for an unknown key (A-5.6); it now
probes for a changed one too, and looks up what was trusted in the `known_hosts`
lines it already has. `KnownHostsService.replace` is deliberately a separate
method from `trust`, which keeps refusing a changed key, so that replacing can
only happen through the endpoint meant for it.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/repo-credentials.md` (RC-21's data, RC-22 to
RC-24); `docs/architecture/git-engine.md` A-5.6; `docs/requirements/repo-add.md`
AR-32.

## Global Constraints

- The shared constraints of [the step 3 index](2026-11-02-00-roadmap-step-3.md)
  apply.
- `replace` deletes the user's rows for that host and port and inserts the new
  key, in one transaction. It is for that user only. The instance-wide list is
  never changed (RC-23).
- The log line is at `info`: the user ID, host, port and both fingerprints, and
  no secret (RC-24).
- If the probe fails (the server went away), the error still says
  `host-key-changed`, without a new key, and `replace` cannot be called for it.
- Host keys for a port other than 22 are `[host]:port`, as A-5.6 says.

## Review Focus

- **A key changed for a built-in host:** the instance's old line stays in the
  known-hosts file next to the user's new one, and `ssh` must accept the new key
  → Task 2 test `RC-23: a user's new key for a built-in host works, and for that
  user only`.
- **Replacing for a host whose key has not changed,** or a key other than the
  one the server shows, must not widen what's trusted → Task 2 test `replaces
  only a host and port already known`. The backend computes the fingerprint from
  the key in the body and stores that, so that a client cannot pair a key with
  another key's fingerprint.
- **A different key type on the same host** (the known one is RSA, the server
  offers Ed25519) is reported as changed (A-5.6) with both types → Task 1 test
  `reports both key types`.
- **Port 2222 replaced** must not touch port 22 → Task 2 test `replaces only
  that port`.
- **Another user's trust** is untouched → Task 2 test `does not change another
  user's known hosts`.
