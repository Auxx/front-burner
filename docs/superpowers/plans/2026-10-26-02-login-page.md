# Login Page and App Header Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 2 of [the index](2026-10-26-00-roadmap.md): the operator logs in
on the login page, lands on the page they asked for or on the dashboard, stays
logged in while the auth token is refreshed in the background, and logs out from
the user menu of the app header, in every tab at once.

**Architecture:** `web/core` gets the auth session (tokens in `localStorage`,
one refresh at a time across tabs with the Web Locks API), an HTTP interceptor
that adds the token and refreshes once on `auth-token-expired`, the route guards
and the current user. Everything the shell needs at startup goes through the
`@front-burner/web-core/app` entry point (A-8.1). A new `web/shell` library
holds the app header, the user menu and "Page not found"; it is loaded lazily
with the first page that needs it. A new `web/feature-dashboard` library holds
the dashboard page, which plan 6 fills in.

**Tech Stack:** as in the onboarding plan. No new packages.

**Spec:** `docs/requirements/auth-login.md` (LG-1, LG-3, LG-4, LG-6, LG-9 to
LG-11, LG-14 web half, LG-39, LG-40, LG-68); `docs/requirements/navigation.md`
(NV-1 to NV-3, NV-5 to NV-8, NV-13, NV-17 to NV-19; NV-7 without Preferences and
the version line, see the index); `docs/requirements/dashboard.md` DS-1, DS-2.
Architecture: `web-client.md` A-8.1, A-8.4, A-8.14; `modules.md` A-2.5.

## Global Constraints

- The shared constraints of [the index](2026-10-26-00-roadmap.md) apply.
- Uses plan 1's API exactly: `AuthApi.methods()`, `AuthApi.login()`,
  `AuthApi.refresh()`, `AuthApi.logout()`, `MeApi.current()`; the header
  `REFRESH_HEADER` with value `1`; the error codes `auth-token-expired`,
  `unauthenticated`, `wrong-credentials`, `refresh-refused`.
- The initial bundle stays within the 300 KB gzipped budget (NF-2.9):
  `web-core/app` imports only types from `shared/contracts`, never a schema, and
  `web/shell` and every feature are loaded lazily. `npx nx build web` passes the
  budget check after every task that touches `apps/web` or `web-core/app`.
- Fixed texts: "Wrong username or password" (LG-14), "You have been logged out"
  (LG-39), "Your session has expired. Please log in again" (LG-40), "This page
  doesn't exist." (NV-3); the HTTPS warning: "This instance is not served over
  HTTPS. You will be logged out when your session token expires." with the link
  text "How to set up HTTPS" to
  `https://github.com/Auxx/front-burner/blob/master/docs/wiki/deployment.md`
  _(plan's call: the wording of LG-68's warning)_.
- Page titles (NV-13): "Log in · Front Burner", "Dashboard · Front Burner",
  "Page not found · Front Burner".
- The narrow-screen layout of the header applies below the `$medium` breakpoint
  (600 px) of `libs/ui/src/styles/mixins/_breakpoints.scss` _(plan's call for
  NV-6)_.

## Review Focus

- **A return target that leaves the web client** (`returnUrl=//evil.example`,
  `/\evil.example`, `https://evil.example`, `javascript:…`) must land on the
  dashboard, never off-site (LG-4) → Task 3 test `refuses a return target
  outside the web client`.
- **Two tabs whose auth tokens expire together** must send one refresh request,
  and the second tab must use the token the first stored, not refresh with the
  rotated refresh token (which revokes the session, LG-36) → Task 1 test `uses
  the token another tab stored while it waited` and Task 7 test `two tabs share
  one refresh`.
- **A request that fails with 401 after the retry** (the session was revoked
  meanwhile) must log the user out with the session-expired message, not retry
  in a loop → Task 2 test `retries only once`.
- **The backend unreachable on logout** must still remove the auth token and
  show the login page (LG-39) → Task 1 test `logs out locally when the backend
  cannot be reached`.
- **`localStorage` holding a corrupt or old value** (another version's shape,
  invalid JSON) must count as logged out, not crash the start of the web client
  → Task 1 test `treats an unreadable stored session as logged out`.

### Task 1: The auth session in `web/core`

**Files:**

- Create (generated, `toolkit-nx` service in feature `core` of `web-core`):
  `libs/web/core/src/core/services/auth-session/auth-session.service.ts` (+
  `.spec.ts`)
- Create: `libs/web/core/src/core/models/login-message.model.ts`
- Modify: `libs/web/core/src/app.ts`, `libs/web/core/src/index.ts`

**Interfaces:**

- Produces:
  - `type LoginMessage = 'logged-out' | 'session-expired' | 'password-reset'`;
    the login page reads it from the navigation's `history.state.loginMessage`
    (LG-9).
  - `AUTH_STORAGE_KEY = 'front-burner.auth'`; the stored value is `{ authToken:
    string; authTokenExpiresAt: string; refreshTokenExpiresAt: string }`
    (LG-40). Anything else under the key counts as no session.
  - `AuthSessionService` (`providedIn: 'root'`):
    - `readonly loggedIn: Signal<boolean>`;
    - `authToken(): string | undefined`;
    - `login(email: string, password: string): Promise<void>` — `login` with
      `refreshTokenDelivery: 'cookie'`, stores the tokens; rejects with the
      `HttpErrorResponse`;
    - `refresh(failedToken: string): Promise<string>` — inside
      `navigator.locks.request('front-burner.refresh', …)`: if the stored token
      differs from `failedToken`, returns it without a request (LG-40);
      otherwise calls `refresh` and stores the result; on failure calls
      `expire()` and rejects;
    - `logout(): Promise<void>` — calls `logout` (any error ignored), clears the
      stored session, navigates to `/login` with `loginMessage: 'logged-out'`
      (LG-39);
    - `expire(returnUrl?: string): Promise<void>` — clears, navigates to
      `/login?returnUrl=…` with `loginMessage: 'session-expired'` (LG-40);
    - listens to `storage` events: when another tab removes the key, this tab
      clears its state and goes to `/login` with `'logged-out'` (NV-8); when
      another tab stores a new token, `loggedIn` follows.

- [ ] **Step 1: Write the failing tests** (`AuthApi` replaced by a stub,
      `navigator.locks` by a fake that runs callbacks one at a time):
  - `stores the tokens after login and reports loggedIn`;
  - `treats an unreadable stored session as logged out` (`'{'` and `{"x":1}`);
  - `refreshes once and stores the new token`;
  - `uses the token another tab stored while it waited` (the stored token
    changes before the lock is granted: no request);
  - `expires the session when the refresh fails` (navigates with
    `'session-expired'` and the return URL);
  - `logs out locally when the backend cannot be reached`;
  - `follows a logout in another tab` (dispatch a `StorageEvent` with `newValue:
    null`).
- [ ] **Step 2: Run them and see them fail** — `npx nx test web-core`.
- [ ] **Step 3: Implement the service**; export it and `LoginMessage` from both
      entry points.
- [ ] **Step 4: Run them and see them pass** — `npx nx test web-core && npx nx
      lint web-core`.
- [ ] **Step 5: Commit** — `feat(web-core): keep the auth session`

**Interfaces:**

- Consumes: `AuthSessionService` (Task 1).
- Produces: `authInterceptor: HttpInterceptorFn`:
  - for URLs under `/api/v1/auth/session/` adds `REFRESH_HEADER: 1` and no

    `/api/v1/onboarding` adds `Authorization: Bearer <token>` when there is one;

    retries the request **once** with the new token (LG-40); a second `401`, a
    `401 unauthenticated`, or a failed refresh calls `expire(router.url)` and
    rethrows.
