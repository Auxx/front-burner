# Unlock API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 59 of [the step 3 index](2026-11-02-00-roadmap-step-3.md): a
client can ask which credentials a repository uses and whether its key is
locked, wrong passphrases are limited per key, and a session's tabs hear when a
key is unlocked.

**Architecture:** The unlock endpoint exists since plan 10. This adds a read
endpoint in `server/feature/repositories`, which already knows both repositories
and credentials; an in-memory `UnlockAttempts` window in the credentials
library; and a publish to one session's streams from `KeyUnlockStore`, which
every way of unlocking goes through.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/repo-credentials.md` (RC-1, RC-7's read side,
RC-16's event, RC-18, RC-20; the API for criterion 10);
`docs/architecture/api.md` A-3.11; `docs/architecture/git-engine.md` A-5.5.

## Global Constraints

- The shared constraints of [the step 3 index](2026-11-02-00-roadmap-step-3.md)
  apply.
- At most **5** wrong passphrases per key per user per minute. A sixth attempt,
  right or wrong, is `429 unlock-too-many-attempts`, before the key's KDF runs
  (RC-18, A-5.5). The existing `ssh-key-unlock` group, 10 per IP, stays.
- `key.unlocked` (`{ type: 'key.unlocked'; keyId: number }`) goes only to the
  streams of the session that unlocked the key (A-3.11, RC-20).
- Reading a repository's credentials does not restart the unlock's idle timer
  (`touch: false`).
- The response carries public parts only (A-3.5, AC-REPO-002.14).

## Review Focus

- **A key the user does not own** must be `404` before any attempt is counted,
  so that one user cannot use up another's window → Task 1 test `does not count
  an attempt on another user's key`.
- **Attempts on one key** must not limit another → Task 1 test `limits each key
  on its own`.
- **The window sliding,** not a fixed minute that lets 10 through across its
  edge → Task 1 test `allows an attempt again 60 seconds after the oldest wrong
  one`.
- **A correct passphrase within the limit** clears the count, and the map must
  not grow without end → Task 1 test `forgets a key's attempts after a success
  and after the window`.
- **A second session of the same user** must neither get `key.unlocked` nor be
  told unlocked → Task 2 test `AC-REPO-002.15`'s API half: `an unlock reaches
  only its own session`.
