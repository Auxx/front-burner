# Editor Bytes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 163 of [the step 6 index](2026-11-16-00-roadmap-step-6.md), Part
F: after plan 162, the editor's chunks load in one wave beside the file, but
NF-2.2 still misses on slow 4G (`docs/wiki/release-checks.md`, "Plan 162: round
trips"):

| Row                          | After plan 162 (p95, reference host) | Target |
| ---------------------------- | ------------------------------------ | ------ |
| NF-2.2 Editor usable, 100 KB | 2.33 s (desktop), 2.49 s (phone)     | 2 s    |

What is left is bytes: the editor's two chunks are 169 KB and 124 KB of Brotli,
1.6 s at slow 4G's 180 KB/s on top of the round trip. Read from the build's
metafile (`dist/apps/web/browser-stats.json`), two things in them are not needed
to type:

- **The preview's Markdown pipeline, in the main thread's chunk.** The editor
  pane's chunk holds `libs/web/markdown`'s `render-safe-html.ts` and everything
  it imports (unified, remark, `rehype-raw` with `hast-util-raw` at 203 KB
  before compression, micromark, `character-entities`), although A-8.13 runs the
  pipeline in the preview worker. Nothing outside `libs/web/markdown` uses it:
  it is there because `libs/web/markdown/src/index.ts` exports `renderSafeHtml`,
  and the module builds its pipeline at its top level, so the bundler keeps it
  whenever the entry point is imported. Taking that one export out of the entry
  point (tried, then reverted, while writing this plan) shrinks the editor
  pane's chunk from 124 KB to 27 KB of Brotli: 98 KB, about 0.55 s on slow 4G.
- **HTML, CSS and JavaScript grammars in CodeMirror's chunk.** `markdown()` of
  `@codemirror/lang-markdown` refers to `@codemirror/lang-html` through its
  default `htmlTagLanguage`, which brings `lang-css` and `lang-javascript` with
  their Lezer grammars: about 172 KB of the chunk's 581 KB before compression
  (`@lezer/javascript` alone 95 KB). The editor uses them only to highlight HTML
  tags in Markdown (`tok-tagName`, `tok-attributeName` in `editor-state.ts`).
  `commonmarkLanguage`, which `markdown()` uses as its base, does not need them,
  and the package is side-effect free, so importing it alone leaves them out.

After this plan the editor starts with the Markdown language alone, and the HTML
language arrives in its own chunk after the editor is ready; the pipeline stays
in the worker; and the build fails when either comes back into the editor's
chunks.

**Architecture:**

- **The pipeline leaves the entry point.** `renderSafeHtml` and `SafeHtml` are
  no longer exported from `libs/web/markdown/src/index.ts`; the specs that use
  them already import `./pipeline/render-safe-html` by path. Nothing else
  changes in the worker or the preview.
- **The HTML language, loaded after the editor is ready** _(plan's call: the
  highlighting is the same as now, a moment later; leaving HTML tags
  unhighlighted would change what the editor shows, which ED-9 does not ask for,
  and the lazy chunk costs one request that no measure waits for)_. In
  `libs/web/code-editor`:
  - `editor-state.ts` highlights with `yamlFrontmatter({ content: new
    LanguageSupport(commonmarkLanguage) })`, the **basic language**, until the
    **full language** has loaded; `@codemirror/lang-markdown` is imported for
    `commonmarkLanguage` only.
  - A new `state/markdown-html.ts` exports `MARKDOWN_WITH_HTML`, today's
    `yamlFrontmatter({ content: markdown({ codeLanguages: [], addKeymap: false
    }) })`, and is imported only dynamically, so the bundler puts it and
    `lang-html` in a chunk of their own, outside the chunk map's `editor` group
    (which follows static imports only, A-8.18).
  - `loadHtmlInMarkdown(): Promise<void>` (in `editor-state.ts`) imports it once
    and keeps it; `upgradeLanguage(state: EditorState): TransactionSpec | null`
    swaps the highlighting compartment's basic language for the full one, when
    the state highlights and the full language has loaded, and `null` otherwise.
    `setHighlighting(true)` and `createEditorState` use the full language once
    loaded. `isHighlighting` is true for either language.
  - `CodeEditorComponent` calls `loadHtmlInMarkdown()` after it sets
    `fb:editor-ready` the first time, then dispatches `upgradeLanguage` on its
    view; and dispatches it whenever it is given another state, so that a file
    opened before the load, kept in `OpenFile.editorState`, is upgraded when it
    is shown again.
- **A budget the build checks.** `apps/web/scripts/chunk-map.mjs` fails the
  build when a group holds a forbidden input (Task 1), and when the editor's own
  files (the `editor` group less the `repository-screen` group, which is loaded
  before any file can be chosen) are over **EDITOR_LIMIT_BYTES = 230 KB
  gzipped** _(plan's call: slow 4G leaves NF-2.2's 2 s, less one round trip of
  562.5 ms and about 150 ms to render, for about 230 KB of Brotli at 180 KB/s;
  gzip, which the script can compute before `precompress`, is the larger of the
  two, so the budget has a margin; the same kind of check as NF-2.9's
  `size-check`; Task 2)_. The forbidden inputs of the `editor` group are
  `node_modules/hast-util-raw/`, `node_modules/@codemirror/lang-html/` and
  `libs/web/markdown/src/markdown/pipeline/render-safe-html.ts`.

**Tech Stack:** Angular 22 (`@angular/build:application`), CodeMirror 6
(`@codemirror/lang-markdown`, `@codemirror/language`), esbuild's metafile;
Vitest; Playwright (`perf-screen.mjs`).

**Spec:** `docs/architecture/non-functional.md` NF-2.2, NF-2.9;
`docs/requirements/editor.md` ED-9; `docs/architecture/web-client.md` A-8.1,
A-8.11, A-8.13, A-8.18; `docs/wiki/release-checks.md`, "Plan 162: round trips".

## Global Constraints

- The shared constraints of [the step 6 index](2026-11-16-00-roadmap-step-6.md)
  apply.
- No new variable and no new dependency.
- The editor highlights exactly what it highlights now once the full language
  has loaded: Markdown, YAML front matter, and HTML tags and attributes (ED-9);
  fenced code stays unhighlighted (`codeLanguages: []`), and Enter still does
  not continue lists (`addKeymap: false`).
- NF-2.9's initial JavaScript does not grow: `web:size-check` still passes.
- A-8.18 gets the budget and the lazy HTML language, and A-8.11 the two
  languages, in the same pull request.

## Review Focus

- **Typing while the HTML language arrives** → the swap is one transaction on
  the highlighting compartment: the text, the selection and the undo history
  stay, tested in `editor-state.spec.ts`.
- **A file opened before the load and shown after it** → it is upgraded when
  shown, not left with the basic language, tested in the code editor's spec.
- **Highlighting turned off, then on, after the load** → the full language comes
  back, not the basic one; while off, `upgradeLanguage` returns `null`, tested
  in `editor-state.spec.ts`.
- **The HTML chunk fails to load** (offline right after opening a file) →
  `loadHtmlInMarkdown()` rejects, the editor keeps the basic language and logs
  nothing to the console; the next call tries again, tested in
  `editor-state.spec.ts`.
- **A later change brings a grammar or the pipeline back** → the build fails by
  name, tested in `chunk-map.spec.mjs` and, on the real build, by the script
  itself, which `web:precompress`, the image's build and web-e2e all run.

### Task 2: The HTML language after the editor is ready

**Files:**

- Create: `libs/web/code-editor/src/code-editor/state/markdown-html.ts`
- Modify: `libs/web/code-editor/src/code-editor/state/editor-state.ts` (+ spec),
  `libs/web/code-editor/src/code-editor/components/code-editor/code-editor.component.ts`
  (+ spec), `apps/web/scripts/chunk-map.mjs` (`EDITOR_LIMIT_BYTES` to 230 KB),
  `docs/architecture/web-client.md` (A-8.11, A-8.18)

**Interfaces:**

- Consumes: `checkGroups` and `FORBIDDEN` (Task 1).
- Produces: `MARKDOWN_WITH_HTML: Extension` (in `markdown-html.ts`, imported
  dynamically only); `loadHtmlInMarkdown(): Promise<void>` and
  `upgradeLanguage(state: EditorState): TransactionSpec | null`, exported from
  `editor-state.ts` and so from `@front-burner/web-code-editor`. In
  `chunk-map.mjs`: `node_modules/@codemirror/lang-html/` added to
  `FORBIDDEN.editor`; `EDITOR_LIMIT_BYTES = 230 * 1024`; `writeChunkMap(dist,
  groups, limit = EDITOR_LIMIT_BYTES)` throws `editor: N KB gzipped, over the
  230 KB budget (NF-2.2)` when the editor's own files are over it.

- [ ] **Step 1: Write the failing tests** in `editor-state.spec.ts`, which
      resets the loaded language between tests: `highlights Markdown and front
      matter before the HTML language has loaded` (`Frontmatter`, `ATXHeading1`
      in the tree; no `TagName` inside an `HTMLTag`); `highlights HTML tags once
      it has loaded and the state is upgraded` (`TagName` and `AttributeName` in
      the tree of `<abbr title="x">y</abbr>`); `upgradeLanguage keeps the text,
      the selection and the undo history`; `upgradeLanguage returns null while
      highlighting is off, or before the load, or once upgraded`;
      `setHighlighting(true) after the load uses the HTML language`;
      `isHighlighting is true with either language`; `a failed load leaves the
      basic language, and the next call loads again` (the dynamic import mocked
      to reject once). In the code editor's spec: `loads the HTML language after
      fb:editor-ready and upgrades the view`; `upgrades a state that was created
      before the load when it is shown`. In `chunk-map.spec.mjs`: `fails when
      the editor's own files are over the budget, not counting the repository
      screen's` (fixture files of random bytes, a small `limit` passed in), and
      the real-build test extended to `keeps the preview pipeline and the HTML
      grammars out of the editor's chunks, within the budget`.
- [ ] **Step 2: Run them, implement, run them again** — `npx nx run

- [ ] **Step 3: The budget** — `npx nx run web:precompress` passes, then `npx nx

- [ ] **Step 4: Check by hand** — open a Markdown file with an HTML tag in the
