# Push Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 56 of [the step 3 index](2026-11-02-00-roadmap-step-3.md): the
git engine pushes the current branch over HTTPS or SSH, never forced, and says
in an error code why a push failed.

**Architecture:** `GitEngine.push` goes through the existing `runNetwork`, so
the broker, egress proxy and known hosts all apply; `runNetwork` gains a
working-copy `cwd` and the config safety check before every command (A-5.7). All
recognising of push messages is in `git-errors.ts` (RC-5). An in-memory
`NetworkLock` next to `WorkingTreeLock` gives one network operation per
repository (A-5.3); the fetch and pull of step 4 use the same lock. Nothing here
has an endpoint yet.

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/git-advanced.md` (GA-29 to GA-31, GA-41's engine
half); `docs/requirements/repo-credentials.md` RC-5;
`docs/requirements/commit-author.md` CA-15; `docs/architecture/git-engine.md`
A-5.3, A-5.7, A-5.10.

## Global Constraints

- The shared constraints of [the step 3 index](2026-11-02-00-roadmap-step-3.md)
  apply.
- The command is `git push --porcelain --no-follow-tags --no-recurse-submodules
  origin refs/heads/<branch>:<target>`, with `--set-upstream` for an unpublished
  branch. It never has `--force`, `--force-with-lease` or a `+` refspec (GA-30).
  `<target>` is the upstream's ref (`git config branch.<branch>.merge`), or
  `refs/heads/<branch>` when there is none (GA-29).
- Before a push of an unpublished branch from a single-branch clone, `git config
  --add remote.origin.fetch +refs/heads/<branch>:refs/remotes/origin/<branch>`,
  unless it is already there (GA-41), so that its upstream ref exists after the
  push.
- `origin`'s URL in the working copy must equal the repository's stored remote
  URL, otherwise `unsafe-repository-config`. The broker's credentials are for
  the stored URL only.
- New codes in `GIT_ERROR_CODES`: `push-non-fast-forward`, `push-not-allowed`,
  `push-protected-branch`, `push-unsigned`, `push-rejected`. Remote lines (the
  text after `remote: `) go in `params.remoteMessages`, redacted, at most 64 KB.
  They are plain text.
- Push's patterns are tried before the general ones, in this order:
  - `\[rejected\].*\((fetch first|non-fast-forward)\)` →
    `push-non-fast-forward`;
  - the HTTP error `403`, `marked as read only`, `read-only`, `Permission to .*
    denied`, `You do not have write access` → `push-not-allowed`;
  - `protected branch` → `push-protected-branch`;
  - `signed|signature` in the remote lines → `push-unsigned`;
  - `\[remote rejected\]` or `pre-receive hook declined` → `push-rejected`.

## Review Focus

- **A branch name like `-x` or `a:b`:** git's branch rules refuse `:`, and the
  full ref form is what keeps `-x` from being read as an option → Task 2 test
  `pushes a branch whose name starts with a dash`.
- **A token in an error:** stderr and `remoteMessages` must have no credentials
  → Task 2 test `leaves no credentials in the error's detail and params`.
- **A hook message that says `[rejected]` or `403` on a `remote:` line** must
  not be taken for git's own status → Task 1 test `reads git's codes only from
  git's own lines`; remote lines are removed first, except for the signed check.
- **A repository config with `remote.origin.pushurl`:** the check of A-5.7 must
  refuse it, since it would send the push elsewhere → Task 2 test `refuses a
  config with a pushurl`.
- **A shallow single-branch clone** must be able to push and get its upstream
  ref → Task 2 test `pushes a new branch from a single-branch clone`.

### Task 2: The engine's push and the network lock

**Files:**

- Create: `libs/server/core/git/src/lock/network-lock.ts` (+ spec, like
  `working-tree-lock.ts`)
- Modify: `libs/server/core/git/src/engine/git-engine.ts` (+ spec),
  `libs/server/core/git/src/config/repository-config.ts` (+ spec; adds
  `remote.*.pushurl`), `libs/server/core/git/src/git.module.ts`,
  `libs/server/core/git/src/index.ts`,
  `libs/server/core/git/src/testing/git-ssh-server.ts` (accepts
  `git-receive-pack`), `libs/server/core/git/src/testing/git-http-server.ts`
  (option `refusePush: 403`), `docs/architecture/git-engine.md`

**Interfaces:**

- Produces:
  - `NetworkLock.run<T>(repositoryId: number, task: () => Promise<T>):
    Promise<T>`.
  - `GitEngine.push(workingCopy: string, request: { remoteUrl: string;
    credentials: GitCredentials; knownHosts: string[]; branch: string;
    singleBranch: boolean }): Promise<{ commits: number; upstream: string }>`.
    `commits` is counted before the push: `rev-list --count @{upstream}..HEAD`,
    or `rev-list --count HEAD --not --remotes` for an unpublished branch. It
    uses `gitTimeoutMs`.
  - `git-engine.md` A-5.7 lists `remote.*.pushurl` among the refused keys.
