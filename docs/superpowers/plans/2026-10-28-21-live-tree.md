# Live Tree Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or

> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 21 of [the step 2 index](2026-10-28-00-roadmap-step-2.md): the
file tree follows changes made from another tab or device without a reload.
Expanded folders are listed again, folders that are gone disappear, and an open
file deleted elsewhere closes with a message. A repository that finishes cloning
while its screen is open becomes usable without a reload.

**Architecture:** In `web/feature-repository-screen`. A `TreeSync` service,
provided by the page, subscribes to plan 9's `PushChannelService.events` for the
screen's repository: `files.changed` reloads the named folders that are expanded
(all expanded folders for `all`), and `reconnected` reloads every expanded
folder, since events are never replayed (A-3.11). `repository.status` drives
`RepositorySession`. Changes made by this tab are known to `EntryCommands`, so
that their own events never show "deleted elsewhere" (FB-42 applies only to
changes made elsewhere).

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/file-browser.md` (REQ-FILE-001: FB-3's live status,
FB-41, FB-42 without unsaved edits; criterion 21 without the editor half);
`docs/architecture/api.md` A-3.11; `web-client.md` A-8.5.

## Global Constraints

- The shared constraints of [the step 2 index](2026-10-28-00-roadmap-step-2.md)
  apply.
- Only expanded, loaded folders are listed again; a named folder that is
  collapsed or not loaded is ignored (FB-41). Reloads of one folder are
  coalesced: at most one request in flight per folder, and one more after it
  when another event arrived meanwhile.
- A folder whose reload answers `entry-not-found` is removed from the tree and
  from the remembered expanded folders, with no error row (FB-42).
- When the route's file is no longer in its reloaded parent, and this tab did
  not delete or rename it, the editor area shows "This file was deleted or
  renamed elsewhere." _(FB-42's text)_. The route stays, so a reload shows
  FB-13's message.
- A `repository.status` event for the screen's repository: `ready` on the
  not-openable state opens the repository (FB-11 then counts this as the visit's
  one opening); `error` on the open screen shows the not-openable state.

## Review Focus

- **The tab's own delete or rename**, whose `files.changed` event can arrive
  before the HTTP response, must not flash "deleted or renamed elsewhere" → Task
  1 test `ignores its own changes when the event comes first`.
- **A burst of 50 `files.changed` events for one folder** (a script on another
  device) must not send 50 listings → Task 1 test `coalesces reloads of one
  folder`.
- **A reconnect after a long time offline** must bring every expanded folder up
  to date → Task 1 test `reloads expanded folders after a reconnect`.
- **An event for another repository** must change nothing → Task 1 test `ignores
  other repositories`.
- **A repository that turns ready while its screen shows "still being cloned"**
  must open with its tree, and call `open` once → Task 2 test `opens a
  repository when its clone finishes`.

**Files:**

- Create (generated service): `services/tree-sync` (+ `.spec.ts`)
- Modify: `services/file-tree-store/*` (+ spec), `services/entry-commands/*` (+
  spec), `components/editor-area/*`, `pages/repository-screen/*`,
  `apps/web/public/i18n/en.json`

**Interfaces:**

- Consumes: `PushChannelService.events`, `.reconnected` (plan 9); the
  `files.changed` event (plan 17); `FileTreeStore` (plan 16).
- Produces:
  - `EntryCommands.ownChange(path: string): () => void` — marks `path` (and
    everything under it) as changed by this tab until the returned function is
    called, 5 s after the command's response at the latest.
  - `FileTreeStore.reload(folders: readonly string[] | 'all'): void` — with the
    coalescing and removal rules of Global Constraints.
  - `TreeSync.start(repositoryId: number): void` — subscribes until the page is
    destroyed; tells the editor area when the open file is gone elsewhere.
