# View Modes and Scrolling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 31 of [the step 2 index](2026-10-28-00-roadmap-step-2.md): the
user chooses Split, Edit or Preview on wide screens and switches between Edit
and Preview tabs on phones. In Split the editor and preview scroll together;
switching tabs keeps the place in the file. Each device remembers the last view
mode for each screen size.

**Architecture:** In `web/feature-repository-screen`, a `ViewMode` service holds
the mode per screen size, from `injectNarrowViewport()` and per-device memory. A
`ScrollSync` helper maps between the editor's top line and the preview's blocks
through the blocks' `data-from-line`/`data-to-line` (plan 30). The preview
component gains `topLine`, `scrollToLine`, a `scrolled` output and an `active`
input, so that a hidden preview on a phone does no work while the user types
(A-8.12).

**Tech Stack:** as before. No new packages.

**Spec:** `docs/requirements/editor.md` (REQ-EDIT-001: ED-34 to ED-36, ED-39 for
the controls; criteria 20, 21, 24's controls half); `web-client.md` A-8.12.

## Global Constraints

- The shared constraints of [the step 2 index](2026-10-28-00-roadmap-step-2.md)
  apply.
- **Modes** (ED-34): wide screens **Split** (default), **Edit**, **Preview**, as
  a `ui-segmented-control` labelled "View"; narrow screens **Edit** (default)
  and **Preview** as `ui-tab-strip` tabs. Per-device memory keys:
  `fb.<userId>.viewMode.wide` and `fb.<userId>.viewMode.narrow`. A remembered
  value that is not valid for its size is ignored.
- **Hidden preview does no work**: when the preview is not on screen (Edit on
  any screen), `md-preview`'s `active` is false and it neither reads the text
  nor renders; becoming active renders at once (A-8.12, NF-2.4).
- **Split scrolling** (ED-35): scrolling either pane brings the block at the top
  of it to the top of the other, and within that block the same share of its
  height. A scroll caused by syncing never syncs back.
- **Switching** (ED-36): Edit → Preview opens the preview at the block holding
  the editor's top line; Preview → Edit opens the editor at the first line of
  the preview's top block.

## Review Focus

- **Scroll syncing feeding back on itself** (editor scrolls preview, which
  scrolls the editor, …) must not happen, also with momentum scrolling on a
  phone → Task 2 test `does not sync a scroll it caused`.
- **A remembered "Split" on a phone** (memory written by a desktop-sized window
  of the same browser) must not show both panes on a narrow screen → Task 1 test
  `ignores a remembered mode that the screen size does not allow`.
- **A preview block that has not rendered yet** (a big file, scrolled far) must
  not break syncing; the nearest rendered block is used → Task 2 test `uses the
  nearest block when the line's block is missing`.
- **Switching to Preview on a phone while the last update is still in the
  worker** must show the newest text, not the text from when the preview was
  last visible → Task 3 test `renders the newest text when the preview becomes
  active`.
- **Rotating a phone to landscape** (narrow → wide) must switch to the wide
  mode's memory without losing the place in the file → Task 1 test `keeps the
  place when the screen size changes`.
