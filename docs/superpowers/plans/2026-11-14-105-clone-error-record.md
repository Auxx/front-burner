# Clone Error Record Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plan 105 of [the step 5 index](2026-11-14-00-roadmap-step-5.md): a
repository in the `error` status keeps git's error, without secrets, and the ID
of the request that started the clone, so that **Details** can show both
(RM-10).

**Architecture:** Two nullable columns on `repositories`, `error_detail` and
`error_request_id`, beside `error_code`, since they describe the same error and
go with the repository (A-4.5b) _(plan's call)_. Not in `jobs`: finished jobs
are cleaned up (A-6), and the error must last until the user retries. The clone
job's payload carries the request ID, as a job runs outside any request.

**Tech Stack:** as before; a drizzle migration. No new packages.

**Spec:** `docs/requirements/repo-manage.md` (RM-6, RM-10);
`docs/requirements/repo-add.md` (AR-53, AR-54); NF-10.5, NF-10.6;
`docs/architecture/data.md`.

## Global Constraints

- The shared constraints of [the step 5 index](2026-11-14-00-roadmap-step-5.md)
  apply.
- The detail is `GitOperationError.detail`, which the engine has already cleaned
  of credentials (AR-53), trimmed and cut to its last 4,000 characters, as git
  puts the cause at the end _(plan's call)_. A timeout and an interrupted clone
  have no git message: their detail is `null`, and the error code already says
  what happened.
- The request ID is `req.id` of the request that queued the clone (the add
  request now, the retry in plan 112), the same ID as in the log lines and the
  error responses (NF-10.6). A job queued before this plan has none: `null`.
- `WorkingCopyCheck` and `InstanceRepositories.markDamaged` take an optional
  detail, `null` on start, where nothing ran git; plan 109 passes git's message.
- A clone that ends well clears all three columns.

## Review Focus

- **No secret in the record:** a failed clone of
  `https://user:token@host/repo.git` stores no `token` → test `stores no
  credentials`.
- **A long error** is cut from the start, keeping its end → test `keeps the end
  of a long error`.
- **A retried clone that works** leaves no old detail behind → test `a clone
  that ends well clears the record`.
